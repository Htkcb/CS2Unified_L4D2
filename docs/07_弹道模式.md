## 1. `l4n_view_punch_scale`：原实现、默认值、CS2 目标值

### 1.1 原项目（Left4Neko V2.55.0）怎么实现

| 项 | 事实 | 证据 |
|---|---|---|
| 注册 | `ConVar("l4n_view_punch_scale", "1.0", FCVAR_ARCHIVE)`，**默认 1.0**；未设 min/max（0 与 >1 都合法） | `l4n-re.md` §1 |
| 消费点 | 只有一个：`C_TerrorPlayer::CalcView` 虚表槽 `+0x3E0`（slot 248）的替换函数 `left4neko+0x100F7E40` | 同上 §0 |
| 动作 | 保存 `[this+0x1204/08/0C]`（`m_vecPunchAngle` 三轴）→ 各自乘 `m_fValue`（`+0x2C`）→ 调原 `CalcView` → **立刻还原** | 同上 |
| 作用域 | **只在那一次 CalcView 调用里**；`CTerrorGun::FireBullet` 与服务器子弹读到的永远是未缩放值 ⇒ **只改相机，不改弹道/命中** | 同上 |
| 可达范围 | 控制台/cfg 任意实数；L4N 自己的菜单滑条只到 0…1 步长 0.1（UI 限制，不是 cvar 限制） | 同上 |

### 1.2 CS2 的目标值及其依据

CS2 的后坐是**两段消费**：相机消费 `1.104 × 冲量表`，子弹消费 `1.00 × 冲量表`。

| 量 | CS2 实测 | 该发次表值和 | 比值 | 出处 |
|---|---:|---:|---:|---|
| AK-47 30 发相机抬升 | **6.04°** | 5.471° | **1.104** | `HANDOVER` §3.3 / D-035 |

L4D2 的 punch 场是**逐命令衰减的累加器**，实测「相机 / (scale × 表值)」只有 **A ∈ [0.898, 0.921]**（两点反解，D-035）。
所以在 L4D2 里要**看到** CS2 的 6.04°，`scale × k` 必须是 `1.104 / 0.898 ≈ 1.23`；项目当时取 **scale = 1.21**（区间 [1.20,1.23] 内、比最优点低 0.7%）。

⇒ 本栈已经用 **`cs2feel_recoil_scale 1.21`** 把相机幅度做到 **5.95°（比 CS2 低 1.5%）**。
这一层已经承担了 CS2 的相机比例，**因此 `l4n_view_punch_scale` 的 CS2 对应取值是 1.0**（不叠加）。
若再乘 1.10，相机会变成 `1.21 × 1.10 = 1.331 × 标称值`，兑现后 **6.54°（超 CS2 +8%）**——这是"越大越好"的错觉，不是 CS2。

| 参数 | 默认值 | CS2 对应目标值 | 依据 |
|---|---:|---:|---|
| `l4n_view_punch_scale` | **1.0** | **1.0**（本栈） / 结构比 **1.104**（纯相机方案） | CS2 相机 6.04°/表值 5.471° = 1.104；L4D2 的 A=0.898 由 `recoil_scale 1.21` 吸收 |
| 允许误差 | — | 相机抬升 **6.04° ± 0.24°（±4%）**；k 的容差 **1.21 ± 0.02** | D-035 的两点区间 [1.20,1.23] + 实测重复性（5.96 vs 6.04，1.3%） |

**测量口径（判据用）**：AK-47 / 30 发连续 / 不压枪 / 固定站位 / `cl_showpos` 截图法 / 64 tick /
取「第 1 发前 pitch」与「第 30 发时刻 pitch」之差；同一轮必须**无鼠标位移**（yaw 漂移 < 1° 才可用）。
屏幕换算：1280×720、水平 90° ⇒ 1° ≈ 14.2 px；1920×1080 ⇒ 1° ≈ 21.3 px。

## 2. 三种模式：定义与目标值

> 1.0.6 起入口仍是一个**循环行**：`!cs2u` → **手感 / Feel** → 「弹道模式：<模式>（<相机/弹道>，点此切换）」，
> 点一次换一档（**自动 → 单人·TR-40 → 多人 → 自动**）；等价命令 `sm_cs2u_set cs2u_bmode <0|1|2>`。
> 旧值 `3`（1.0.5 的弱爬升 +0.30）自动迁移到 `1`。

1.0.6 用**单人·TR-40**替换了原来的「单人（CS2 原生分离）」——后者是把弹着压在准星下方 0.48°，
既不是玩家想要的观感，又仍需要客户端插件；CS2 原样结构没丢，它现在只由「后坐结构」行 / `cs2_split` 预设负责。

| | **单人·TR-40**（`cs2u_bmode 1`） | **多人**（`cs2u_bmode 2`） |
|---|---|---|
| 谁承担分离 | **服务器**（MOD-5 正偏移，相机不压） | **客户端**（Left4Neko 相机缩放，可选） |
| 服务器 cvar | `recoil_scale 1.00` / `view_scale 1.00` / `ballistics_mode 1` / `ballistics_scale +1.20` / `yaw 1` | `recoil_scale 1.21` / `ballistics_mode 0` / `ballistics_scale 0` / `yaw 0` |
| 相机（30 发 AK） | **4.1–4.25°**（1.00 × 表值 × 0.87 兑现） | 5.95°（1.21 × 表值 × 0.898） |
| 弹道 | **≈9.0°**（2.20 × 表值） | 5.95°（相机 = 弹道，同一个场） |
| 可见分离（准星 vs 弹着） | **+4.98°（弹着高于准星，随每发增大）** | **0°**（除非客户端自己设 k ≠ 1） |
| 客户端要求 | Left4Neko 保持 1.0；**必须装** `cs2feel_aimsync`（`ratio = +1.200000`），否则弹孔贴相机 | 什么都可以不装；想拿 CS2 相机比例的玩家自己设 `l4n_view_punch_scale 1.10` |
| 未装插件时 | 弹孔贴相机 ⇒ 玩家看不到 5° 的爬升（子弹/命中不受影响） | 弹道与所有人**完全一致**，弹孔贴准星 ⇒ **没有所见≠所中** |

**TR-40 观感的可操作定义**：AK-47、10–20 m 贴墙、30 发、不压枪、固定站位，相机累计抬升 **4.1–4.25°**，
弹着累计抬升 **≈9.0°**，**两者之差（弹孔高于准星）4.98° ± 0.11°**——旧 TR-40 台架实测 5.225°
（相机 0.3041° / 服务器 cmd 5.5294°，`oldproj-dossier.md` §3），本模式复现到 **−4.7%**。
第 1/10/20/30 发时弹着 pitch 依次约为 **0.1 / 2.7 / 5.6 / 9.0°**。

> 代价：子弹是 **2.20 × CS2 表值**。这是「k=1（相机不压）+ 弹孔在准星上方」的几何后果，
> 也正是旧项目的「感知夸张档」（当年 matched 默认 2.4）。要 CS2 原样的子弹（1.00 ×）就用「后坐结构」行的匹配/分离。

## 3. 切换入口、默认模式、兼容策略

**入口（1.0.5）**：`!cs2u` → **手感 / Feel** → **「弹道模式：<模式>（<相机/弹道>，点此切换）」** 行，
每点一次循环一档：`自动 → 单人 → 多人 → 单人·爬升 → 自动`。
行内直接显示**实时结构**（`相机 x.xx / 弹道 x.xx`），切换后聊天回显服务器结构与客户端 `cs2feel_aimsync` 期望 ratio。
命令等价：`sm_cs2u_set cs2u_bmode <0|1|2|3>`（受管参数，随配置持久化；1.0.5 起这条命令也会调用 `CS2U_BmodeApply`）。

**默认模式**：`cs2u_bmode = 0`（**auto**）。auto 在拿不到客户端信息时**按未装计**，因此新服的默认观感是 **多人 matched**（安全侧）。

### 3.1 兼容策略与优先级

优先级按用户要求：**① 视觉补偿 → ② 提示 → ③ 禁用爬升**。

| 未装比例 u（未装人数 / 在场人类数） | 生效模式 | 动作 |
|---|---|---|
| **u < 20%** | 单人 | ① **视觉补偿**：服务器保持双通道，让多数人拿到 CS2 结构；少数未装者只损失"弹孔跟随"（误差 ≤ **0.48°**），子弹/命中对他们完全一致 |
| **20% ≤ u ≤ 50%** | 单人 | ① + ②：保持双通道，同时**全场提示一次**「N/M 位玩家未装 aim-sync，弹孔偏差约 0.48°」 |
| **u > 50%** | 多人 | ③ **禁用爬升**：服务器退回 matched（无偏移），所有人弹道一致、无"所见≠所中" |
| 未知（无回答） | 多人 | 按未装计（安全侧），不提示 |

为什么"视觉补偿"排在"禁用"前：禁用会让**所有人**都失去分离（收益归零），而补偿只让少数未装者损失 0.48° 的弹孔精度（子弹/命中不受影响）——代价最小。
为什么 u > 50% 才禁用：超过一半的玩家看不到分离时，"少数人可见的分离"会在同一局里制造两种视觉标准，反而比一致更糟。

### 3.2 同局混合与"队长选择"

- **判定条件**：`u` 按**在场人类**（`IsClientInGame && !IsFakeClient`）计；bot 不计入分子分母。
- **队伍混合**：若某个幸存者队伍内同时存在已装/未装（通过 `GetClientTeam` 分组后各自算 u_team），
  策略升级为 **② 提示**（而不是静默补偿），并在提示里点名未装者 —— 因为同队成员会互相报点，视觉标准不一致最容易吵架。
- **队长**：同队混合时，第一位人类玩家视为队长；提示里给出两条明确选项（"装 aim-sync" 或 "`!cs2u` → 弹道模式 → 多人"），
  由队长决定，管理员可用 `cs2u_bmode` 强制覆盖。
- **冲突处理**：探测器返回 `NotFound` / 超时 = **未装**；返回值与服务器期望的 `ratio` 不一致时按**未装**计并在 `b.detect` 里列出；
  一轮内只提示一次（`g_bBmodePrompted`），换图重置。

## 5. 实测记录（2026-11-03，单人模式的 A4/A5）

台架：**listen server 本地**（64 tick）、`aa_cs2f_a45.smx` 发 AK 并钉住 single 参数
（`view 1.0 / recoil 1.21 / ballistics_mode 1 / scale -0.10 / yaw 1`，控制台有 `PIN a45` 行）、
客户端 `cs2feel_aimsync.ini` 的 `ratio = -0.082645`、`log = 1`、OS 级按住扳机 3 × 3.1 s（每梭 32 发，弹匣 30 发）、
证据在 `docs\evidence\a45-20261103\`（客户端日志 + 探针 `a45.csv` + 控制台）。

| 量 | 实测 | 说明 |
|---|---:|---|
| 相机侧 punch 峰值（每梭） | **5.361 / 5.175 / 5.175** | 均值 **5.24°**，sd **0.09°**（n=3，共 97 发） |
| 名义值 `1.21 × 4.995`（表第 29 行） | **6.04°** | 与 CS2 实测 6.04° **逐位同值**——这是 1.21 这个 scale 的定义 |
| 实测/名义 | **0.87** | = 引擎「写入→消费」之间一个命令的衰减（D-035 的 A=0.898 就是它） |
| 弹道累计抬升（干净满梭） | **5.156°** | 模型 `(1−0.0826) × 5.24 = 4.81°`，实测 +7% |
| 弹道抬升（另两梭） | 4.407 / 1.509 | 基线带上一梭残留的 punch；1.509 那梭结尾弹匣打空 |

**读法与结论**

- **名义（`1.21 × 表值`）与 CS2 的 6.04° 完全一致**：这是配置本身定义出来的，不需要实测。
- **实际被相机消费的是 5.24°**（我们的口径：客户端每发读到的 punch 场值），比名义低 13%，
  与 D-035 的 `A = 0.898` 吻合。D-035 文档里的 5.96° 是 `cl_showpos` 在**写入当拍**读到的值，
  读数口径不同（5.96 vs 6.04 = −1.3%），不是矛盾。
- 因此 A4 的判据应写成 **「实测 5.24° ± 0.15°，且等于 0.87 × 名义 6.04°」**；
  直接拿 5.95/6.04 去卡这个口径会假失败。A5 的判据是 `(1+ratio) × 相机峰值`，实测落在 +7% 内。
- **A6（弹孔像素级跟随）仍未测**：需要同一帧里同时看到弹孔与弹着，属于截图测量，留待下一轮。
