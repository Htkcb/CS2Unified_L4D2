# 00 · 整合设计

> 范围：`CS2Unified_L4D2` v1.0.1 的模块划分、回调分发顺序、失败策略与“为什么合成一个 `.smx`”。
> 事实来源：`src\cs2unified.sp`、`src\cs2u_*.sp`、`src\feel\*`、`src\movement\*`、`tools\sync_sources.ps1`、`tools\verify.ps1`、`tests\results\runtime-smoke.md`。
> 代码与本文冲突时以代码为准；未验证项标 `UNVERIFIED`。

---

## 1. 设计目标与硬约束

| 目标 | 约束来源 | 落地方式 |
|---|---|---|
| 两个上游能力同时可用 | 两者都要 hook `OnPlayerRunCmd`、都要写 `sv_*`/玩家速度 | 合并进一个 `.smx`，由入口文件显式排序 |
| 上游可继续升级 | 上游是只读依赖，不能就地改 | `tools\sync_sources.ps1` 机械重命名，`-Check` 证明 `src\` = 上游 + 重命名表 |
| 对外接口不变 | 已有服务器/配置/其它插件依赖 `cs2feel_*`、`cs2movement_*`、`sm_cs2feel_*`、`CS2F_*` natives | 重命名表**只动内部符号**；ConVar/命令/native 名逐项守恒（见 `tests\results\_audit_extract.txt`） |
| 新增管理面可关可查 | 管理面不能成为新的单点故障 | `cs2u_enable` 开关 + 6 个统一层 ConVar + 独立诊断命令 |
| 失败不产生半配置状态 | 服务器不能因为一个坏值变成“一半 CS2、一半 L4D2” | 全链路 fail-closed：先校验后写、整份拒绝、`.bak` 恢复、预设失败回滚 |

非目标：改写上游行为算法、支持 Linux、把数据层 VPK 变成热切换、提供反作弊能力。

生成规则（`sync_sources.ps1`）：

1. 用正则删除每个模块文件的 `public Plugin myinfo = { ... };`，替换为注释占位（`/* [CS2Unified] Plugin myinfo removed ... */`）；
2. 按有序表做 `\bWord\b` 整词替换（feel 14 条、movement 19 条，见 `docs\01_符号映射表.md`）；
3. 以 UTF-8（无 BOM）写回 `src\feel` / `src\movement`；
4. `-Check` 模式不写盘，只比较“上游 + 重命名表”与磁盘内容，供 `verify.ps1` 判 drift。

> 为什么必须重命名：SourcePawn 的 `#include` 是**文本拼接**。两个上游各自定义的 `public void OnPluginStart()` 合并后就是**同名函数重复定义**（编译错误）；即使能编过，两个 `OnPluginStart` 也都是 SourceMod 回调，会各自触发，顺序不可控。因此重命名不是“可选清理”，而是合并的**前提**。

## 3. 为什么是单个 `.smx`

### 3.1 备选方案对比

| 方案 | 回调顺序 | 管理面访问模块状态 | 部署/版本 | 结论 |
|---|---|---|---|---|
| A. 三个 `.smx`（feel + movement + 管理） | 由 SourceMod 加载顺序决定，**无法保证** feel 先于 movement | 需要给 movement 新增 natives 才能读 `g_iSpreadOffset` 之类内部状态 | 三个文件、三个版本，易漂移 | 否 |
| B. 两个 `.smx` + 管理面走 natives 通信 | 同上不可控 | 可行但要改上游（新增 natives/forward） | 三个文件 | 否 |
| C. **单 `.smx`（本项目）** | 入口文件里**显式写死**顺序 | 直接读同名编译单元内的变量/函数（`CS2M_MoveApplyGlobal`、`g_bSigReady`、`g_iSpreadOffset`、`CS2F_ConfigWeaponCount`） | 一个 `.smx` + 固定 gamedata/配置 | **是** |
| D. 只做数据层 VPK | 无运行时钩子 | — | — | 无法提供后坐力/移动 |

### 3.2 收益

1. **顺序确定**：`OnPlayerRunCmd` 里 feel 一定先于 movement（见 §4.4）；这是“手感读到原始按键、移动再改速度”的前提。
2. **状态可共享**：统一层的 `sm_cs2u_status` 直接读 `g_bActive` / `g_bSigReady` / `g_iSpreadOffset` / `CS2F_ConfigWeaponCount()`；预设应用后直接调 `CS2M_MoveApplyGlobal()` + `CS2M_MoveReassertGlobal()` 让全局 `sv_*` 立刻重新收敛。
3. **原子部署/回滚**：一个 `.smx`、一份统一配置、一份 `install-manifest.csv`；不存在“feel 升了 movement 没升”的中间态。
4. **单版本号**：`CS2U_VERSION` 与 `[CS2Unified] LOAD ... feel=0.5.7-m11 movement=0.5.2` 一行日志即可核对三方版本。

### 3.3 代价（必须接受的）

| 代价 | 具体表现 | 缓解 |
|---|---|---|
| 符号冲突必须机械重命名 | 9 个真实重名符号 + 其余回调/命令回调统一前缀 | 重命名表可审计；`verify.ps1` 检查重命名生效 |
| 单一崩溃域 | 任一模块崩溃会带走整个插件 | 上游各自 fail-closed 保护保留；诊断命令可分层定位 |
| 编译与产物更大 | 体积随源码变化（上一版 Data 498,544 B / Total 785,396 B） | 可接受（SM 插件数据上限内）；最新产物 127,985 B，大小以 build 输出为准 |
| 升级上游需重跑同步 | 上游改动不会自动进入 | `sync_sources.ps1` + `verify.ps1` + 运行时回归（`docs\01` §7） |

## 4. 回调分发顺序及理由

入口文件里所有 SourceMod 回调只有一份，函数体只做“按顺序转发”。

```text
AskPluginLoad2      → CS2F_AskPluginLoad2
OnPluginStart       → CS2F_OnPluginStart → CS2M_OnPluginStart → CS2U_OnPluginStart → LOAD 日志
OnConfigsExecuted   → CS2M_OnConfigsExecuted → CS2U_OnConfigsExecuted（起 0.5 s 一次性定时器）
OnMapStart          → CS2U_OnMapStart（预缓存曳光精灵 materials/sprites/laserbeam.vmt）
OnPlayerRunCmd      → CS2F_OnPlayerRunCmd → CS2M_OnPlayerRunCmd → 合成返回值
OnClientPutInServer → CS2M_OnClientPutInServer
OnClientDisconnect  → CS2M_OnClientDisconnect
OnPluginEnd         → CS2U_OnPluginEnd → CS2M_OnPluginEnd → CS2F_OnPluginEnd
OnClientSayCommand  → CS2U_OnClientSayCommand
```

> `bullet_impact` **不是** SourceMod forward，而是 `cs2u_visual.sp` 在 `CS2U_VisualInit()` 里 `HookEvent("bullet_impact", Event_BulletImpact, EventHookMode_Post)` 注册的事件回调；它不经过入口分发，也不参与 `OnPlayerRunCmd` 的顺序。
>
> SourceMod 1.12 **没有** `OnPostThink` forward（在 `scripting\include\*.inc` 全量搜索无结果）。入口文件里的 `public void OnPostThink` 已在修复 L-01 时删除，`verify.ps1` 第 28 项会检查它不回归。movement 的 PostThink 逻辑由它自己 `SDKHook(client, SDKHook_PostThink, CS2M_OnPostThink)` 驱动（`src\movement\cs2movement.sp:155`），不要把它误删。

### 4.1 `AskPluginLoad2`：只给 feel

`CS2F_AskPluginLoad2` 做两件事：校验 `GetEngineVersion() == Engine_Left4Dead2`（否则 `APLRes_SilentFailure`），并注册 7 个 `CS2F_*` natives。movement 没有 `AskPluginLoad2`，也不需要引擎校验（它靠 DHooks/gamedata 自己的守卫）。

### 4.2 `OnPluginStart`：feel → movement → 统一层

理由：上游先把自己的 ConVar、gamedata、配置表建立起来，统一层最后再建自己的 6 个 ConVar、注册命令/菜单、读统一配置。

```text
CS2F_OnPluginStart()   // 校验签名、载入 configs/cs2feel/*.cfg、创建 cs2feel_* ConVar
CS2M_OnPluginStart()   // 创建 cs2movement_* ConVar、缓存 sv_*、载入武器表、注册命令、AutoExecConfig
CS2U_OnPluginStart()   // 11 个 cs2u_* ConVar（含 VisualInit 的 4 个 tracer，含 alpha）→ 参数/预设/配置/菜单初始化 → 注册 10 个 sm_cs2u* 命令
PrintToServer("[CS2Unified] LOAD version=%s feel=%s movement=%s", ...)
```

注意：`CS2U_OnPluginStart` 里**不会**应用持久化值——那时 `OnConfigsExecuted` 还没跑，`sv_*` 也还没被 movement 应用；应用统一交给 §4.3 的定时器。

### 4.3 `OnConfigsExecuted`：movement 先，统一层 0.5 s 定时器最后

```text
CS2M_OnConfigsExecuted()          // 校验配置 → 若 enable&&apply_global：ApplyGlobal + ReassertGlobal + 起 5 s 收敛定时器
CS2U_OnConfigsExecuted()          // CreateTimer(0.50, Timer_UApplyPersisted, _, TIMER_FLAG_NO_MAPCHANGE)
   └─ 0.5 s 后：ApplyPersistedSettings() → ReconcileMovement() → "PERSIST-APPLY params=N preset=X"
```

为什么统一层要**推后 0.5 s**：

1. `cs2movement` 用 `AutoExecConfig(true, "cs2movement")` 生成/执行 `cfg\sourcemod\cs2movement.cfg`；该执行阶段在 `OnConfigsExecuted` 附近，若统一层在回调里同步写值，可能被随后的 cfg 覆盖。代码注释（`cs2u_core.sp:132-142`）明确把“AutoExecConfig 与 cs2movement.cfg 在本回调之后执行”作为设计依据。
2. L4D2 会在开图后把 `sv_maxspeed` 等重置回默认（上游 D7 实测约 +12.3 s 落点），movement 因此自带 **5 s 收敛定时器**；统一层在 0.5 s 应用完 settings 后再调 `CS2U_ReconcileMovement()`，让全局层立刻按新 `cs2movement_*` 值重新 apply + reassert，而不是等下一轮收敛。
3. 持久化设置必须“最后赢”：否则管理员保存的 `cs2feel_recoil_scale 2.4` 会在每次换图后被 `cs2movement.cfg` / `server.cfg` 里的旧值覆盖。

定时器句柄**故意不保存**：`TIMER_FLAG_NO_MAPCHANGE` 会在换图时关闭它，保存句柄反而会拿到失效句柄；插件卸载时 SourceMod 会自动清理挂起的插件定时器。

`Timer_UApplyPersisted` 的行为：`cs2u_enable 0` 时直接 `Plugin_Stop`；`CS2U_ApplyPersistedSettings()` 返 0（无 settings 或有非法值）时不打 `PERSIST-APPLY`。

### 4.4 `OnPlayerRunCmd`：feel 先，movement 后（**不要交换**）

```c
Action feelResult = CS2F_OnPlayerRunCmd(...);   // 读未修改的 IN_ATTACK，写 cmd angles
Action moveResult = CS2M_OnPlayerRunCmd(...);   // 可能消费/改写 buttons，执行 per-player 速度
if (feelResult == Plugin_Changed || moveResult == Plugin_Changed) return Plugin_Changed;
if (feelResult == Plugin_Handled || moveResult == Plugin_Handled) return Plugin_Handled;
return Plugin_Continue;
```

- **feel 必须先**：弹道层（MOD-5）以“玩家是否按住开火键”为输入，并写出 usercmd 角度；如果在 movement 之后跑，movement 的蹲伏模型可能已经清掉/改写 `buttons`（`cs2u_modes.sp` 与 `cs2unified.sp` 的头部注释都记录了这一点），弹道会读到被污染的输入。
- **movement 必须后**：它的 per-player 跑速/蹲速在 `OnPlayerRunCmd`/`OnPostThink` 里写 `m_flMaxspeed` 与 `CMoveData`，属于“本 tick 的最终裁决”，应当看到 feel 已经处理完的 cmd。
- 两个模块通过**同一组引用参数**（`buttons`、`angles`）串联：feel 对 `angles` 的修改后，movement 看到的已经是修改后的值——这是合并后的预期行为，也是“顺序写死”的意义。
- 返回值合成规则如上。现状：两个模块的源码都只返回 `Plugin_Continue` 或 `Plugin_Changed`（`cs2feel_core.sp:505`、`cs2movement.sp:183`），所以 `Plugin_Handled` 分支**当前不可达**。注意：若未来某个模块开始返回 `Plugin_Handled`，现有顺序（先判 `Changed`）会把“阻断命令”降级成“已修改命令”——这是独立审计 L-02 记录的一个未来风险，不是当前 bug。

### 4.5 其余回调

| 回调 | 转发目标 | 说明 |
|---|---|---|
| `OnPostThink` | **无（入口已删除该函数）** | SourceMod 1.12 没有 `OnPostThink` forward；真正的 PostThink 由 movement 自己的 `SDKHook_PostThink` 驱动，且仅当 `cs2movement_write_timing 1` 时写速度（默认 `write_timing 0` 在 RunCmd 写） |
| `OnMapStart` | `CS2U_OnMapStart` | 预缓存 `materials/sprites/laserbeam.vmt` 并清空每客户端曳光节流时间；失败只记 `TRACER-SPRITE-MISSING`，曳光降级为 no-op |
| `bullet_impact` 事件 | `Event_BulletImpact`（在 `CS2U_VisualInit` 里 `HookEvent`） | 曳光绘制路径；**不是 forward**，不经过入口；只对存活、非 bot、队伍 2（幸存者）生效，50 ms/客户端节流 |
| `OnClientPutInServer` | `CS2M_OnClientPutInServer` | 重置每玩家状态、缓存地址、`SDKHook_PostThink` |
| `OnClientDisconnect` | `CS2M_OnClientDisconnect` | 解 hook、清状态 |
| `player_jump` 事件 | `CS2M_Event_PlayerJump`（在 `CS2M_OnPluginStart` 里 `HookEvent`） | movement 的跳跃状态；它不是 SourceMod 公共回调，重命名只为命名空间一致 |
| `OnClientSayCommand` | `CS2U_OnClientSayCommand` | 默认不做任何拦截；仅 `cs2u_menu_chat_alias 1` 时接管可选别名 `!menu` / `!c2u`（主入口 `!cs2u` 由 SourceMod 原生映射）；见 `docs\02` §6 |

### 4.6 `OnPluginEnd`：统一层 → movement → feel（与启动相反）

```text
CS2U_OnPluginEnd()   // 清 g_bUConfigLoaded（当前仅此）
CS2M_OnPluginEnd()   // 拆三条 detour、CS2M_MoveRestoreGlobal() 逐个恢复 sv_*、释放武器表
CS2F_OnPluginEnd()   // 拆 feel 的 hook
```

让管理面**先失效**再拆特性层，避免拆卸过程中管理面（菜单/定时器/命令）再次触发写入；movement 必须在 feel 之前恢复全局 `sv_*`，否则恢复动作本身可能被仍在生效的 feel 逻辑观察。当前 `CS2U_OnPluginEnd` 只清一个标志，顺序的实际影响很小，但依赖方向是明确的。

## 5. 数据流

### 5.1 单参数写入（菜单 / `sm_cs2u_set` / 预设 / 持久化共用一条通道）

```text
来源（菜单 v:idx:cand / sm_cs2u_set / 预设条目 / 配置 settings）
  → CS2U_ParamValidate(idx, value)     // 数字语法 → 范围 → bool 只能 0/1 → int 必须整数
  → CS2U_ParamSet(idx, value)          // 再校验一次，然后 SetConVarInt/Float
  → ConVar 变更钩子（上游模块自己的 OnSpreadChanged / OnRecoilChanged / ...）
  → 模块内部重新计算（如 CS2F_ApplySpreadConfig）
  → 需要时 CS2U_ReconcileMovement()    // cs2movement_enable && apply_global 才 apply+reassert
```

被拒绝的写入**不会碰到 ConVar**（`CS2U_ParamSet` 先校验后写），因此不存在“半应用”。

**单参数改动会立即持久化（H-01 已修复并复验）**：`Cmd_Set` 与 `MenuHandler_Value` 在 `CS2U_ParamSet` 成功后调用 `CS2U_PersistLive()`——先 `ConfigWriteInternal`（写盘），成功后才更新内存持久表并回显 `(persisted)`；写盘失败则**保留旧的持久表**并提示 `but persistence failed: <原因>`（此时内存里的 ConVar 已改、磁盘还是旧值，换图会回退到旧值）。复验：`set 2.4` → `changelevel` → 仍 `2.400`。

### 5.2 预设应用（原子性）

```text
CS2U_ModeApply:
  1. 整个预设 dry-run 校验（任一非法 → 整条拒绝，什么都不写）
  2. CS2U_Snapshot()                  // 快照 23 个参数 + 当前 preset 名（rollback 用）
  3. 逐条 ParamSet
  4. g_sActivePreset = name；cs2u_preset = name
  5. CS2U_ReconcileMovement()
  6. CS2U_ConfigWriteInternal(name, includeSettings=true)
       失败 → CS2U_Rollback() + 报 "could not be persisted; rolled back"
  7. CS2U_CapturePersisted()（把当前值写进内存持久表）
```

### 5.3 启动/换图时序

```text
加载插件
  OnPluginStart → feel/movement/统一层初始化
  OnConfigsExecuted
    movement: 校验 + apply sv_*（若 enable&&apply_global）+ 启动 5 s 收敛定时器
    统一层: 起 0.5 s 一次性定时器
  +0.5 s: 应用 settings（无 settings 则 applied=0）→ reconcile movement
  +5 s  : movement 收敛定时器把被引擎重置的 sv_* 拉回目标值
换图
  定时器因 TIMER_FLAG_NO_MAPCHANGE 关闭 → 新一轮 OnConfigsExecuted 重复上述过程
```

实测日志（`tests\results\runtime-smoke.md`）：`CONFIG-OK initial load: presets=5 (invalid=0) settings=accepted active=(none)`、`changelevel` 后仍恢复 `cs2_matched` / `recoil scale 2.400`（新版本首启为 `presets=6`）。

### 5.4 曳光（视觉辅助，独立于参数通道）

```text
OnMapStart → CS2U_OnMapStart(): PrecacheModel("materials/sprites/laserbeam.vmt") → g_iTracerSprite
bullet_impact（每个弹丸触发一次，EventHookMode_Post）
  → tracer_enable 0 / 精灵 <= 0            → Continue（no-op）
  → 客户端 <=0 / 不在游戏 / 已死           → Continue
  → IsFakeClient / team != 2（幸存者）     → Continue
  → now - last[client] < 0.05 s            → Continue（霰弹多弹丸只画一条）
  → GetClientEyePosition(start) + 事件 x/y/z(end)
  → TE_SetupBeamPoints(... width, life, color) → TE_SendToAll()
```

它是**纯视觉**：只发 temp entity，不写 ConVar、不改伤害/命中判定、不参与预设快照。`cs2_tracer` 预设只是把 `cs2u_tracer_enable` 设为 1，其余条目与 `cs2_matched` 相同。

### 5.5 受伤减速（injury，movement 0.5.1）

```text
cs2movement 每 tick 重写 m_flMaxspeed（CS2 武器速度层）
  → 低血量时引擎把 m_flMaxspeed 压到 survivor_limp_walk_speed（85），
    但下一 tick 又被武器速度覆盖 → 20 HP 仍全速
  → injury 层读取当前目标：
      health != 0 且 health <= 阈值（0 = 引擎阈值）
      temp_health 1 时把临时生命计入
      adrenaline 1 且处于肾上腺素 → 不减速
      ratio 模式：target = CS2 目标 * (injury_speed / injury_base)   // 默认 132/220 = 60%
      absolute 模式：target = injury_speed                           // 默认 132
  → 把该武器这一 tick 的 m_flMaxspeed 钳到 target
```

因此 injury 是“**在武器速度层之后**再钳一次”，不是修改引擎跛行阈值；`injury_health 0` 只表示“沿用引擎判定为跛行的时机”。它由 movement 模块执行，不经过统一层参数通道（统一层只负责把 7 个值校验后写入 ConVar）。

## 7. 关键容量常量

| 常量 | 值 | 影响 |
|---|---:|---|
| `CS2U_MAX_PARAMS` | **40** | 受管参数上限；当前 36（feel 11 + movement 15 + injury 7 + tracer 3），`verify.ps1` 检查“非空且不超过 40” |
| `CS2U_MAX_CANDIDATES` | 8 | 每个参数的菜单候选值上限；当前最多 5 个 |
| `CS2U_MAX_PRESETS` | **12** | 预设上限（7 内置 + 2 DIY + 余量）；DIY 槽位保存后才出现 |
| `CS2U_MAX_ENTRIES` | **40** | 单个预设条目上限（24→32→40）；`cs2_full` / `cs2_competitive` 的 36 条可完整装入 |
| `CS2U_NAME_LEN` | 32 | 预设名长度（字节） |
| `CS2U_VALUE_LEN` | 32 | 值字符串长度（字节） |
| `g_sConfigText` | 49,152 | 配置文本缓冲；超过会被 `ReadFileString` 截断并因解析失败被拒绝 |

## 8. 设计上明确不做的事

1. 不把上游逻辑改成“统一钩子”——保留各自 hook 与门控，出问题时可单独关闭（`cs2feel_enable` / `cs2movement_enable`）。
2. 不让统一层接管上游 ConVar 的默认值；`cs2u_params.sp` 只声明“可改的范围与候选”，默认值仍在上游 `CreateConVar` 里。
3. 不做 `cs2u_enable` 的“全局静默”：它只门控菜单入口、聊天别名、预设应用与换图定时器；`sm_cs2u_set/save/reload/rollback` 仍可用（见 `docs\03` §7）。
4. 不把数据层 VPK 纳入预设：预设只写 ConVar，数据层是部署期选择。
