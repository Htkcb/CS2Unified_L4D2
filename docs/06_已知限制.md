## L1 · 数据层不可热切换

**事实**：`addon\cs2feel_r2_plugin.vpk` 里是 **13 个** `scripts\weapon_*.txt`，只改写 7 个扩散键（`SpreadPerShot`、`MaxSpread`、`SpreadDecay`、`MinDuckingSpread`、`MinStandingSpread`、`MinInAirSpread`、`MaxMovementSpread`）。这些文件由引擎在**加载期**解析，SourceMod 没有运行时替换 VPK 内容的 API。

**后果**：

- 7 套预设与 36 个受管参数**只覆盖运行时 ConVar**；任何“扩散形状”的差异都必须换 VPK + 重启（服与客户端都要）。
- 预设里没有、也不可能有数据层字段；`cs2_matched` / `cs2_split` 的“匹配/分离”是**后坐力与弹道**层面的，不是扩散形状层面的。
- 数据层与插件应视为同一发布单元：只换插件不换 VPK（或反之）会造成“同一组参数、不同弹道”的不可复现问题。

**额外约束（来自 VPK 内 `addoninfo.txt`）**：

1. `cs2feel_spread_mode` 必须保持 **0**；启用插件 spread 模块会让扩散有两个来源。本项目的 `vanilla`/`cs2_matched`/`cs2_split` 都显式写 `spread_mode 0`，但这只是预设默认值——管理员仍可在菜单里改成 1。
2. 不要同时启用 `cs2feel_vscript_pure.vpk`（覆盖同一批脚项）。

## L4 · 平台与构建绑定

- **Windows only**：`gamedata\l4d2_cs2feel.txt` 头部明确写 “PLATFORM SCOPE - WINDOWS ONLY”，全文没有 `linux` 键；`cs2movement.txt` 的三个签名也只有 `windows`。Linux 上 feel 会 fail-closed（不激活），movement 引擎层会降级为仅全局 `sv_*`。
- **绑定单一 `server.dll`**：`PatchVersion 2.2.4.3`，9,130,288 B，SHA256 `A93EC916A8F26FBEA85688C321D2BA8DD346D435FAB09A0B926DD950C2E1EA12`。游戏更新后签名失配 → feel 拒绝激活、movement 引擎层关闭（不会崩服，但功能消失）。
- **SourceMod 1.12**：实测 `1.12.0.7230`、编译器 `1.12.0.7210`；未在 1.11 或 2.x 上验证。`cs2feel_core.sp` 里还有针对 SM 1.12 行为的专门处理（gamedata 缺失时 `LoadGameConfigFile` 会抛异常）。
- 语法层面用到了 `#pragma newdecls required`、`dhooks`、`sdkhooks`、`menus`，均需对应扩展/包含。

## L5 · 64 tick 与 `cs2feel_spread_tick_profile`

| 事实 | 值 |
|---|---|
| L4D2 默认 tickrate | ~30 Hz（上游实测 29.9） |
| 64 tick 的前提 | **L4DToolZ + tickrate enabler**；仅加 `-tickrate` 无效（上游 D8） |
| 项次运行时环境 | 启动日志 `[L4DToolZ] tickrate: 64`，`runtime-smoke.md` 也记为 64 tick |
| `cs2feel_spread_tick_profile` | `0`=off（默认）、`1`=auto、`2`=force 30-tick、`3`=force 60-tick、`4`=force 64-tick |
| AUTO 的识别范围 | 28.5–31.5 Hz → 30-tick；63.5–65.5 → 64-tick；57.0–63.5 → 60-tick；**其它（含 100 tick）一律 NONE（保持 off）** |

关系与建议：

1. 该 ConVar 属于 **feel 的 spread 模块**（`cs2feel_spread.sp` 的 TR-31 profile）。spread 默认 `mode 0`（pass-through，不写扩散），所以本项目的 7 套预设里 profile 实际是**惰性**的——除非管理员把 `spread_mode` 改成 1。
2. 本项目**没有**把 `cs2feel_spread_tick_profile` 纳入 36 个受管参数，也没有在任何预设里设置它：菜单改不了、配置不持久化。要改只能走 `server.cfg` 或 `cfg\sourcemod\cs2movement.cfg` 之外的 feel 侧通道（feel 故意没有 `AutoExecConfig`，见 `cs2feel_core.sp:422-425`）。
3. 若在 64 tick 服上启用 spread 模块，应显式设 `1`（auto，会识别 64）或 `4`（force 64）；`3`（force 60）在 64 tick 下是错的档位。
4. 本项目只在 64 tick 做过一轮功能冒烟，**没有**做 30 vs 64 的对比测量；30 tick 的结论全部来自上游文档。

## L6 · movement 的服务器单边修正与预测代价

以下数字**全部来自上游** `..\CS2Movement_L4D2\README.md` 的 D1–D11 与对应 `tests\`，本项目未复测。把它们当“上游交付的已知代价”，不要在本项目文档里二次夸大。

| 上游 ID | 内容（摘要） | 对统一层用户的含义 |
|---|---|---|
| D1 | 蹲速按武器对齐，但有**摩擦下限**：AK 目标 73.1 被 `duck_speed_min 76` 抬到 76；64 tick 实测 73.31（1/16 速度量化吃掉净增益） | 默认 `duck_speed_min 76` 时，低于 75.64 的蹲速不会精确等于 CS2 |
| D2 | 预测代价：`m_flMaxspeed` 是网络字段且进 prediction copy；30 tick 下 0/60/100 ms RTT 无可测回拉（<1 u）；**64 tick 下 Δv=65 换档在 RTT100 回拉 6–10 u**；蹲速另有固定 1–6.6 u/s 差、run→duck 回拉 1.7–2.1 u | 大幅改 `cs2movement_maxspeed`（例如 320→150）在 64 tick + 高延迟下可能看到换档回拉 |
| D3 | 地面可持续最小 wishspeed = 80×5.2/5.5 = **75.64 u/s**；低于它会塌（30 tick cap60→11.0；64 tick→5.12） | 不要把 `cs2movement_maxspeed` 设到 <76 当“慢速模式” |
| D4 | 属性写路径（`m_flMaxspeed`/`m_bDucked`/`m_vecVelocity` 等）**已被运行时证伪**，相关开关默认 0 | 不要打开 `crouch_enforce`/`write_timing`/`jump_enforce`/`bhop_*` 期待效果 |
| D5 | 签名绑定 `server.dll A93EC916…`；更新后须重扫，否则 fail-closed | 与 L4 同一条风险 |
| D6 | bot（含特感 bot）也受速度上限影响：幸存者 bot 从原生 220 变为按武器表（230/240）；**特感 bot 的 `weapon_*_claw` 不在表里，回退 `base_speed 250`**；对 AI 寻路/配合的影响未评估 | 合作/对抗服会改变 bot 行为，需要单独观察 |
| D7 | 全局 `sv_*` 由插件**独占**：L4D2 开局后会把 `sv_maxspeed` 重置回 1000，插件用 5 s 收敛定时器拉回；管理员手工改这 7 个 cvar 会在 ~5 s 内被改回 | 改速度请改 `cs2movement_*`，不要直接改 `sv_*` |
| D8 | 30 tick / 64 tick 双基线；64 tick 需 L4DToolZ + tickrate enabler | 见 L5 |
| D9 | `lowspeed_sustain`（opt-in，默认 0）：让 <75.64 的目标可持续（AK 73.09/73.12、cap 60→60.00），代价是**服务器单边修正**（客户端仍按 vanilla 衰减预测，每 tick 修正 1.34/2.87 u/s @W=60）；**64 tick 不要与 `duck_speed_min 76` 同用** | `cs2_competitive` 预设会打开它并把 `duck_speed_min` 设为 0——这是有意的 |
| D10 | `air_jump_speed`（opt-in，默认 0）：L4D2 每次跳跃自动进蹲伏 hull，空中加速只有 CS2 的 0.35 倍；开启后服务器侧恢复，但**客户端预测仍按引擎自动蹲**；64 tick 实测 100 ms RTT 下最大位置滞后 0.30 u | 空中加速的“手感”不可能在客户端完全一致 |
| D11 | `crouch_slide`（opt-in，默认 0）：跑动中按蹲保留动量、指数衰减；64 tick 0.10 s≈13.0 u、0.20 s≈25.9 u；`pull_u` 只 +0.15 u。0.5.x 起 `crouch_slide_time` 出厂默认 **0.20（CS2 等价）**，并成为受管参数 | 滑行距离与 tick 相关，30/64 tick 不同；`crouch_slide 1` 但蹲速层未就绪时静默不滑（看 `ready=`） |

三条使用建议：

1. 这三个 opt-in 层（D9/D10/D11）**默认关闭**，只有 `cs2_competitive` 预设会一起打开；它同时把 CS2 后坐力通道归零。要保留 matched 手感 + 三个 opt-in，用 `cs2_full`。
2. 任何“CS2 完全一致”的说法都不成立：这些层是**服务器权威值**对齐，客户端预测仍可能不同步。
3. 出现“跑动/跳跃有拉扯”时，先关掉 opt-in 层（`air_jump_speed`/`lowspeed_sustain`/`crouch_slide`）再判断。

## L7 · bot 与全局 `sv_*` 独占

- **bot**：见 L6 的 D6。补充一条本项目视角的风险：`cs2movement_maxspeed` 与 `weapon_speed_mode` 是 **ROOT 参数**，一次误设会同时改变所有 bot 与玩家的上限；本项目没有针对 bot 的额外保护（上游也没有）。
- **`sv_*` 独占**：见 D7。统一层的 `CS2U_ReconcileMovement()` 只调 `CS2M_MoveApplyGlobal()` + `CS2M_MoveReassertGlobal()`，不额外延长收敛窗口；因此“手工改 `sv_maxspeed` 被改回”的行为与上游一致。

## L9 · 配置损坏、半写与回滚落盘

| 场景 | 行为 | 风险 |
|---|---|---|
| 语法坏 / 缺 `presets`+`settings` / 全部预设非法 / settings 有非法值 | **整份拒绝**，保留上一版内存表与实时值；`sm_cs2u_reload` 回复带 `(previous tables kept)` | 管理员会看到“改了没生效”，需要看 `config error` |
| 配置超过 32 KiB | 被 `ReadFileString` 截断；代码注释的预期是随后解析/section 检查失败并整份拒绝，但**这条路径未实测**：若截断点落在合法结构内，理论上可能“部分加载”（独立审计 L-05） | 正常 8 预设×23 条目约 18 KB，不会触发；不要手工造超大配置 |
| 保存过程中崩溃（`rename → export` 之间） | **已修 M-05**：下次启动检测到“主文件缺失 + `.bak` 存在”会先恢复 `.bak`（`CONFIG-RESTORED-FROM-BAK`）；主文件存在但被拒时改名 `.corrupt` 再恢复一次（`CONFIG-RECOVERED-FROM-BAK`） | 恢复逻辑未在真实崩溃窗口下模拟（UNVERIFIED） |
| 回滚时落盘失败 | **已修 M-02**：值在内存恢复，但命令**返回失败**并提示“下次换图会重新应用旧 settings”；日志 `ROLLBACK-PERSIST-FAILED` | 未制造磁盘故障实测（UNVERIFIED） |
| 导出失败（磁盘满等） | 删除半成品、把 `.bak` 改回原名，返回失败，并回读上一次配置；内存预设表**先不改**（M-04：写成功后才提交，新增预设失败则回退 count） | 未制造磁盘故障实测（UNVERIFIED） |

## L20 · `cs2_full` 的边界：36 个受管值 ≠ 整个引擎

**它是什么**：`cs2_full`（完全仿真 CS2）由 `CS2U_ModesBuildFull` 构造，基于 movement **0.5.2**，**显式写死 36 个受管值**：

| 组 | 值 |
|---|---|
| feel（11） | enable 1；recoil mode 1 / scale 1.0 / view 1.0；ballistics 0 / 0.0 / yaw 0；spread mode 0 / scale 1.0 / move 0 / posture 0 |
| movement（15） | enable 1、apply_global 1、engine 1、duck 1、air_jump 1、lowspeed_sustain 1、crouch_slide 1、**crouch_slide_client 1**、**crouch_slide_time 0.20**、**crouch_slide_min_speed 100**、crouch_enable 1、maxspeed 1000、weapon_speed_mode 1、duck_speed_min 0、base_speed 250 |
| injury（7） | enable 1、mode 1（ratio）、health 0、speed 132、base 220、temp_health 1、adrenaline 1 |
| visual（3） | tracer 0、width 1.0、life 0.2 |

**它不是什么**：

1. **不是整个引擎的等价**：未纳入统一层的 ConVar（如 `sv_accelerate`、`sv_friction`、`sv_airaccelerate`、`sv_gravity`、`cs2movement_accelerate`、`cs2feel_spread_tick_profile`、`cs2movement_bhop_*` 等）**不在** 36 个受管值里；它们仍由 `cs2movement.cfg`（AutoExecConfig）或上游默认值决定。`cs2_full` 只保证“这 36 个值确定”，不保证“所有 engine 参数都是 CS2 值”。
2. **不换数据层**：扩散形状仍在 VPK 的 `scripts\weapon_*.txt` 里；`cs2_full` 只把 `cs2feel_spread_mode` 设为 0（不启用插件 spread 模块）。
3. **滑行是近似**：`cs2movement_crouch_slide 1` 是项目对 **CS2 蹲下过渡**的近似（跑动中按蹲保留一段动量、按指数衰减到蹲速；64 tick 实测约 13.0 u / 0.10 s、25.9 u / 0.20 s；30 tick 约 11.2 / 31.7 u）。它**不是** CS2 里独立存在的“滑铲技能”。要严格无滑行：把 `cs2movement_crouch_slide` 设为 0。**新增的 `crouch_slide_time 0.20` 是 CS2 等价时间常数**（`ln(215/73.1)/5.2 = 0.207 s`），只让滑距落在 CS2 量级；`crouch_slide 1` 但蹲速层未就绪（`sm_cs2u_status` 的 `ready=0`）时依然不会滑。
4. **曳光关**：CS2 没有服务端曳光；`cs2_full` 显式 `cs2u_tracer_enable 0`。想要视觉辅助请用 `cs2_tracer`。
5. **容量**：`cs2_full` 有 36 条，`CS2U_MAX_ENTRIES` 现在是 **40**；每次加载都会 `CS2U_ModesEnsureFull()` 重建内置 `cs2_full`，旧配置里的截断定义会被纠正。

**与其它预设的关系**：

- `cs2_matched` = 所见即所中，但移动 opt-in（air_jump/sustain/slide）保持默认关，且不含 injury（保持当前值）；
- `cs2_competitive` = 纯移动：三个 opt-in 全开 + 后坐力通道归零，36 条全量显式写入（含 injury 7 项与滑行 3 项）；
- `cs2_full` = matched 手感 + 三个移动 opt-in 全开 + injury 7 项 + **全部 36 个受管值显式写死**；
- `cs2_tracer` = matched + 曳光开，移动 opt-in 与 injury 不写。

## L21 · 受伤减速（injury）是服务器单边修正

**事实**（`src\movement\cs2movement_injury.sp`，movement 0.5.1）：

- injury 在 cs2movement 的**武器速度层之后**再钳一次 `m_flMaxspeed`；它不修改引擎的跛行阈值，也不改客户端预测。
- 默认 `mode 1`（ratio）：`target = CS2 目标 * (injury_speed / injury_base)` = `132/220 = 60%`；`mode 0`（absolute）则固定 132。AK 215→129、SMG 240→144。
- `injury_health 0` 表示**沿用引擎判定为跛行的时机**（L4D2 约 40 HP），不是关闭；关闭请用 `injury_enable 0`。
- `injury_temp_health 1` 把临时生命计入；`injury_adrenaline 1` 让肾上腺素期间不减速。

**限制**：

1. **客户端预测/回拉**：服务器每 tick 重写速度，客户端仍可能看到短促的加速/回拉；这是 movement 层既有代价（L6），injury 不消除它。
2. **只对幸存者**：injury 是幸存者速度层的一部分，特感/观察者不受影响。
3. **真人观感未验证**：服务端状态（`injury_enable=1` / `injury_speed=132`）正确，但“20 HP 时走起来是否像 CS2”需要真人实测。
4. **调参边界**：`injury_speed 0` 或 `injury_health 0` 都有“交回引擎”的含义，混用会得到完全不同的结果；文档与预设默认值见 `docs\03` §6。

- 分离只存在于**客户端**：Left4Neko 的 `l4n_view_punch_scale` 在 `C_TerrorPlayer::CalcView` 里 save → 乘 → 还原，`FireBullet` / 弹孔 / 服务器弹道读到的仍是未缩放字段（静态证据见 `CS2FeelVScript_L4D2` 的 `l4n-re.md` / `engine-re.md`，实测见 `sep-20261101/`）。
- 它是客户端 ConVar（flags 仅 `FCVAR_ARCHIVE`），没有 `FCVAR_SERVER_CAN_EXECUTE` ⇒ 服务器 `ClientCommand` 会被拒（与 D-041 的 `+attack` 同理）。所以 `!cs2u` 的「相机 / 准星」页**只读不写**：`QueryClientConVar` 检测 + 回显推荐值，玩家自己粘贴 `l4n_view_punch_scale 1.10`（或 `0`）。
- 服务器侧唯一的“分离”是「后坐结构」页（或等价的预设 `cs2_split`，`recoil_scale 1.10` + `ballistics_mode 1` + `ballistics_scale -0.10`）：它**对所有客户端生效**；弹孔是否跟随取决于**那个客户端**装没装 aim-sync（`cs2feel_aimsync.dll` + ini，上游 D-058），没装时弹孔仍画在相机方向（行尾注记已改为「弹孔要看客户端装没装 aim-sync」）。

**限制**：

1. **没装 L4N 的客户端拿不到客户端分离**，只能靠「后坐结构」页的 split（没装 aim-sync 时弹孔不跟随）；且服务器无法替任何人打开它。
  装了 aim-sync 的客户端能让**弹孔**也表达这层分离（AK 满自动约 0.53°），但仍有 **L11**：客户端预测吃的是上一条命令的 punch，可见后坐比真实子弹滞后一发份（实测 1.76°）——这条是服务端写 punch 的架构代价，客户端组件消不掉。
2. **客户端 k 不受预设控制**：它存在客户端 `config.cfg`，换预设不会重置；和 `cs2_split` 叠加会得到“相机 1.21× + 服务端偏移”的混合体（应用 `cs2_split` 时插件会对发起者做一次异步查询并提示）。
3. **L4N 升级要复验**：它用 vtable patch（`C_TerrorPlayer` slot +0x3E0），L4N 版本/`client.dll` 更新后需重跑端到端（相机峰值 ~10% 差、`bullet_impact` 逐位相同）。
4. **性能/公平**：两条路的命中判定完全一致；差别只在渲染相机的视觉反馈（k=0 时相机冻结、弹道整条爬升），属于体感选择，不是命中率差异。

**事实**：

## L23 · menu.cfg 误配的回退语义

- 解析失败、未知/重复/空 order 项、>20 可调键、`auth.priority != steamid`：**整段回退内置默认布局**，同时清空 auth → flag 模式。
- 单条 auth 格式错：只跳过该条（`MENU-CONFIG-AUTH-SKIP`），其余生效。
- 回退不会改动 `cs2unified.cfg`（参数/预设），只影响菜单布局与鉴权；管理员下次开菜单收到提示，状态页 `menu config error:` 常驻。
- 不建议把 `menu.cfg` 当“热改菜单项”的工具：项 id 必须在代码里有实现，配置只能改**顺序/可见性/权限/鉴权**。

## L24 · 水面减速（1.0.10，movement 0.5.3）

**事实**：

- `m_nWaterLevel` 在 L4D2 服务端存在（`sm_dump_netprops`：`offset 575`，`bits 2`，Unsigned；datamaps 里是 `Save|Key` 1 字节），但**它是否随玩家下水实时更新**只验证了“属性可读 + 干地为 0”，**没有**真人进水样本。
- 只作用于**幸存者**（`CS2M_IsSurvivor`），感染者/特感/Tank 完全不变；也**没有**改任何 `sv_*` 或全局速度。
- `weapon_speed_mode 0`（原生速度模式）时 `MoveEngineTarget/MoveDesiredMaxSpeed` 提前返回 -1，水面层**不生效**——这是设计，不是 bug。
- 服务器单边写更低的 `m_flMaxspeed`，客户端仍按原生水中速度预测 → 与蹲速层同类的**小幅回拉**，幅度未测。
- level 3（游泳）公式上会减速，但 L4D2 游泳可能不走 `m_flMaxspeed`；**未实测**，若确认无效按“跳过 level 3”处理。
- 与受伤减速**叠乘**（先 limp 再 water，两者都只降不升）；`slowdown` 上限 0.8，factor 下限 0.05。

**剩余风险**：水边来回踩会带来轻微速度抖动（服务端每 tick 重写）；`menu.cfg` 旧文件里没有这两项时靠 `CS2U_OrderAppendMissing` 追加到页尾，位置可能与新装环境不同（内容一致）。

## L25 · 武器速度表可改，但它是“部署资产”

- 菜单「详细移动数值」/`sm_cs2u_weapons` 改的是 `configs/cs2movement_weapons.cfg`，**立即写盘**，
  所以换图、`sm_cs2movement_reload`、重启都不会回退。

## L26 · 特感边界：哪些能动特感、哪些不能（1.0.13）

结论先给：**逐玩家的效果已经全部只作用于幸存者；唯一共享的是引擎物理 cvar，它天然无法按队拆分。**

### L26.1 逐玩家路径（全部已按队隔离）

| 层 | 写什么 | 门控 | 证据 |
|---|---|---|---|
| movement · engine_speed | `m_flMaxspeed` | `CS2M_IsSurvivor` | `cs2movement_move.sp:511`、`842` |
| movement · duck_speed / crouch | `m_nDuckTimeMsecs` / `m_bDucking` / `m_vecViewOffset` | 同上 | `cs2movement_crouch.sp:187` |
| movement · lowspeed_sustain | `CGameMovement::Friction` pre/post 修正 | 同上（按 playerAddr 反查 client） | `cs2movement_move.sp:1607/1775/1979` |
| movement · crouch_slide | 速度衰减 + 复制属性 `survivor_crouch_speed` | 同上 | `cs2movement_move.sp:1290/1299` |
| movement · 空中速度 | `m_flMaxspeed`（含空中） | 同上 | 同一 SetupMove 钩子 |
| movement · injury / water | 目标速度上限 | `CS2M_IsSurvivor` + `IsPlayerAlive` | `cs2movement_injury.sp:295/411`、`cs2movement_water.sp:189` |
| unified · 曳光 | temp entity（纯视觉） | `GetClientTeam(client) != 2` 直接跳过 | `cs2u_visual.sp:59` |
| **feel · recoil** | `m_vecPunch`（`CS2F_PUNCH_OFFSET`） | **1.0.13 新增门控** | `cs2u_core.sp` `CS2U_ShouldRunFeel` |
| **feel · ballistics** | `cmd angles`（弹道抬升） | 同上 | 同上 |
| **feel · spread** | 开火者武器的 spread 字段 | 同上 | 同上 |

1.0.13 之前 feel 三层是**唯一**没有队伍门控的逐玩家路径。它们由 `OnPlayerRunCmd` 驱动，
引擎对谁都调——而特感不开枪，所以那三层在特感身上只可能做坏事：recoil 键在共享的
`IN_ATTACK` 位上（爪击、扑击、舌头都用它），spread 会去写开火者的武器对象。
现在 `cs2u_feel_survivor_only`（默认 **1**）在入口处跳过**只有 3 队（特感）**：
幸存者、旁观者、未分配一律原样通过，所以"保留原有全部效果"是构造上成立的。

> 想回到 1.0.13 之前的行为：`cs2u_feel_survivor_only 0`（改回全队生效，不需要重编）。

`sm_cs2u_status` 有一行 `team gate: feel_survivor_only=1 feel_skipped_infected=N
movement_skipped_non_survivor=M` —— 两个计数器就是这两套门控真的在拦人的运行时证据
（movement 的计数器从 0.4.7 起就有，`sm_cs2movement_status` 里叫 `non-survivor skips`）。

### L26.2 共享路径（改不了，但已经减到最小）

`cs2movement_apply_global 1` 会写这几条引擎 cvar，**所有玩家（含特感）都用它们**：

| cvar | CS2 目标 | L4D2 原版 | 对特感的影响 |
|---|---|---|---|
| `sv_accelerate` | 5.5 | 10 | 有：地面加速曲线变"重" |
| `sv_friction` | 5.2 | 4 | 有：停得慢一点 |
| `sv_stopspeed` | 80 | 100 | 有：低速收尾不同 |
| `sv_airaccelerate` | 12 | 10 | 有：空中微调略强 |
| `sv_gravity` | 800 | 800 | **无**（同值） |
| `sv_maxvelocity` | 3500 | 3500 | **无**（同值） |
| `sv_maxspeed` | —— | 1000 | **不写**：0.4.8 起刻意排除，因为它同时压住 Charger 冲锋（`z_charge_max_speed 500`） |

这不是偷懒：L4D2 的 `CGameMovement` 从**全局 cvar** 读摩擦/加速，没有"按队"的入口。
要逐玩家实现，只能在 `Friction`/`Accelerate` 里重算一遍引擎数学，风险是把幸存者的手感也改坏
（违反"保留原有全部效果"）。所以给的是**选择**而不是偷偷折中：

- 想让特感**完全原版**：`cs2movement_apply_global 0`。幸存者的逐人上限（engine_speed / duck /
  slide / injury / water）仍然生效，但**失去** accel/friction 曲线——这是"CS2 移动手感"里最重的
  那一块，请自行权衡。
- 想保留完整手感：保持 1（默认），并接受特感跟着这 4 条全球值走。

### L26.3 没有验证到的部分

  判定口径：`sm_cs2u_status` 的 `feel_skipped_infected` 在有人变特感时应当开始增长；

- Tank 属 3 队，因此同样被 feel 门控跳过；它的石头是 projectile，本来也不经过 bullet 路径。
