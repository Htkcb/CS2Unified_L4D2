## 1. 用户原话与它的真实含义

> 「做菜单里一键适配本机环境（tick啥的）」

拆成三条可验收的：

1. **探测**：菜单/命令里能看见这台服务器的真实环境（tick 频率、专用服还是本机 listen、tick 增强插件在不在、当前 spread 档位、客户端 rate 类值）。
2. **适配**：一次点击，把与 tick 相关的受管值改成该环境下的推荐组合；**要么全改，要么一个不改**（不允许改一半）。
3. **可见**：改动前能看到"将要改什么"（旧值 → 新值），改动后能看到"改了什么"，并且**能一键回到改动前**。

> ⚠️ 注意「本机」二字：用户说的不是「本机电脑」，而是**这台服务器跑在什么形态上**。
> 同一个插件包可能被放在 30 tick 的单机 listen server，也可能在 64 tick 的专用服，
> 两者的推荐值不一样。所以适配的输入是**探测结果**，不是写死的常量。

---

## 2. 为什么这件事值得做（而不是"加个开关"）

现在这套插件的所有 tick 相关结论，都是**假设 64 tick** 得到的：

| 证据 | 位置 |
|---|---|
| 蹲速 64 tick 实测 73.31（1/16 量化吃掉净增益） | `docs/06` D1 |
| 64 tick 下 Δv=65 换档在 RTT100 回拉 6–10 u | `docs/06` D2 |
| `crouch_slide` 滑距按 tick 实测（0.10 s≈13.0 u @64 / 11.2 u @30） | `docs/06` D11 |
| `air_jump_speed` 只在 64 tick 量过（RTT100 滞后 0.30 u） | `docs/06` D10 |
| `lowspeed_sustain` 在 64 tick **不能**和 `duck_speed_min 76` 同用 | `docs/06` D9 |
| 但 `cs2feel_spread_tick_profile` 默认 **0 = off**，从没被打开过 | `docs/06` L5、`src/feel/cs2feel_core.sp:368` |

也就是说：**插件在 30 tick 服上不会自动变"更差"，但它也不会自动变"正确"**——尤其是 spread 的 tick 档位，
用户在 64 tick 服上开着 spread 模块却拿着 30 tick 的系数，看起来"能跑"，实测是错的（L5 第 3 条）。

这个功能的真正价值不是"少点几下"，而是**把"这套值只在 64 tick 成立"这个隐含前提显式化**。

## 3. 现状事实（动手前必须知道）

### 3.1 tick 在本项目里到底影响什么

| 对象 | 是否受管 | tick 相关性 | 现状 |
|---|---|---|---|
| `cs2feel_spread_tick_profile` | **否** | 直接：0=off / 1=auto / 2=强制30 / 3=强制60 / 4=强制64 | 默认 0，**不持久化**（feel 故意没有 `AutoExecConfig`，`cs2feel_core.sp:422` 附近注释） |
| `cs2movement_duck_speed_min` | 是（idx 25） | 中：64 tick 的 1/16 速度量化 + 摩擦下限 75.64 | 默认 76 |
| `cs2movement_lowspeed_sustain` | 是（idx 21） | 高：修正量按 tick 逐帧累加 | 默认 0，`cs2_competitive` 打开并同时把 `duck_speed_min` 设 0 |
| `cs2movement_air_jump_speed` | 是（idx 23，ROOT） | 高：只在 64 tick 量过 | 默认 0 |
| `cs2movement_crouch_slide_time` | 是（idx 20，由 `act:slide_tier` 代表） | 高：滑距 = 时间 × 速度，随 tick 变 | 默认 0.20 |
| `sv_minrate` / `sv_maxrate` / `sv_minupdaterate` / `sv_maxupdaterate` | **否（也不是本插件的领域）** | 客户端插值/回拉 | 插件**从不写 `sv_*`**，这是既有原则，见 §5.2 |

探测可用的 native 已在本机 include 里核实：

| native | 位置 | 用途 |
|---|---|---|
| `float GetTickInterval()` | `timers.inc:173` | `1.0 / interval` = 实际 Hz，**唯一可信来源** |
| `bool IsDedicatedServer()` | `halflife.inc:194` | 专用服 / 本机 listen |
| `bool LibraryExists(const char[] name)` | `sourcemod.inc:512` | 查 **SM 插件/扩展**的库名；**查不到 Metamod 插件** |

> 关于 tick 增强插件：`tickrate_enabler` / `L4DToolZ` 都是 **Metamod 插件**（`.vdf`），
> SourceMod 侧没有官方 API 查它们。**只能间接判断**：L4D2 原版约 30 Hz，
> 实测到 60/64/100 Hz 就说明"有东西打开了它"。菜单文案要写成"实测 64 Hz（推断 L4DToolZ/tickrate_enabler 生效）"，
> **不要**写成"已检测到 tickrate_enabler 已加载"。

本机测试服实测（`<DS_DIR>`）：

```text
[L4DToolZ] tickrate: 64
[L4DToolZ] maxplayers set to 31
addons/ 下同时有 l4dtoolz.{dll,so,vdf} 与 tickrate_enabler.{dll,so,vdf}
```

`tests/lib/ds_harness.ps1:74` 把 `-tickrate 64` **写死**了——要做 30 vs 64 的对照，必须给
`Start-DsServer` 加参数（见 §6.3）。

## 4. 需求拆解（验收标准）

| # | 场景 | 期望 | 判据 |
|---|---|---|---|
| E-1 | `sm_cs2u_env`（控制台） | 打印环境块：hz / interval / dedicated / maxplayers / 当前 spread 档位与解析结果 / 受管 tick 相关项的现值 / 建议值 | 输出里每一项都有来源（"实测"或"来自 cvar X"） |
| E-2 | 菜单 移动与受伤 → 「环境适配」 | 同 E-1 的可读版（中文 + 建议值 + 差异标记 `≠`） | menudump 能看到该行与子页 |

| E-4 | 确认应用 | 只改预览里列出的项；写入走受管通道（clamp + 持久化 + ACTION 日志） | `cs2unified.cfg` 落盘；`PERSIST-APPLY` 行；换图后值仍在 |

| E-6 | 撤销 | 有「回到适配前」一步（保存适配前的快照，可回滚一次） | 应用 → 撤销 → 每个值逐字回到旧值 |
| E-7 | 幂等 | 已经是推荐值时再点一次，预览是"无需改动" | 第二次点击不写盘、不记 ACTION |
| E-8 | 鉴权 | ROOT only（和 `weapon_speeds` 同级） | GENERIC 管理员看不到/点了被拒 |

## 5. 必须先拍板的四个问题

### 5.1 `cs2feel_spread_tick_profile` 怎么进这套东西

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A · 纳入受管（第 40 个）** | 加进 `cs2u_params.sp`、7 套预设各加 1 条（→40 条）、`CS2U_MAX_ENTRIES` 顶满 | 能持久化、能进预设、菜单可改、和其余 39 个一致 | 容量 0 余量；要改 5 处断言与 3 份文档；`feel` 侧"故意无 AutoExecConfig"的设计被绕开（由统一层代为持久化，需在文档里说明这是有意为之） |
| **B · 独立通道（推荐先做这个）** | `cs2u_env.sp` 自己 `FindConVar("cs2feel_spread_tick_profile")` + `SetConVarInt`，值写进 `cs2unified.cfg` 的一个 `env` 段，加载时回填 | 不动容量、不动预设、不动 39 条契约；失败也不会污染参数表 | 它不在 `managed_params` 里，`sm_cs2u_set` 改不了；需要一条独立的持久化路径与回滚 |

**推荐 B**，理由：本次是"按环境对齐"，不是"多一个可调参数"；B 的爆炸半径小得多。
若将来真需要在 preset 里带 tick 档位，再迁到 A（迁移时记得抬 `CS2U_MAX_ENTRIES`）。

### 5.2 要不要写 `sv_*`（客户端 rate 类）

**建议：默认不写，永久不自动写。** 本项目至今**没有**改过任何 `sv_*`（这是 `cs2_full` 的边界说明里
明写的："只保证这 39 个值确定，不保证所有 engine 参数都是 CS2 值"）。
`sv_maxupdaterate` 是**全服生效、影响所有客户端**的值，塞进"一键"里是权限越界。

折中：环境页**只显示**建议值（如"64 Hz 建议 `sv_maxupdaterate 65`"），
如果要做成一键，必须：单独一行、带 `[全服]` 前缀、二次确认、且**不进**"一键适配"的批量里。

### 5.3 一键 = 直接改，还是先预览？

**必须先预览。** 理由：一次改 4–6 个受管值，管理员看不到 diff 就无法回滚、也无法向玩家解释。
现有 `weapon_speeds` 页已经有"点行 → 生效"的先例，但那是**单值**；批量改必须加一道确认。
菜单形态建议：

```text
「环境适配」
  当前环境：64 Hz / 专用服 / 32 槽 / 0 玩家        ← 只读信息行（不可点或点了只回显）
  建议：spread 档位 4（强制 64）、air_jump_speed 1 …
  预览改动：4 项  ≠
  → 确认应用
  → 撤销上次适配（无快照时显示"无"）
```

### 5.4 30 tick / listen server 的语义

- 30 Hz（原版）：`spread_tick_profile` 建议 **2 或 1**（1=auto 会解析成 30），**不要**开 `air_jump_speed`
  （没量过）、**不要**开 `lowspeed_sustain`（D9 的代价在 30 tick 下未测）。
- 64 Hz：`spread_tick_profile` 建议 **4**（强制 64）或 1（auto）；`air_jump_speed` 可开（量过）；
  `lowspeed_sustain` 与 `duck_speed_min > 0` **互斥**，必须二选一。
- listen server（`IsDedicatedServer() == false`）：tick 通常 = 30，且**玩家就是房主**，
  任何服务器单边写速度的回拉都由房主自己承受 → 建议值应更保守（默认不打开任何 opt-in 层）。

## 7. 明确不要做的（边界）

1. **不要**自动改 `sv_*`（§5.2）。
2. **不要**在 `OnMapStart` 里"自动适配"——环境变了（换图后 tick 变）应该**提示**，不是**静默改值**。

3. **不要**把探测结果写死成"64 tick 就是目标"。用户可能在 30 tick 服上就想要 30 tick 的手感。
4. **不要**在 `cs2u_env.sp` 里碰 `m_flMaxspeed` / 任何 per-player prop——那是 movement 层的领域。
5. **不要**为了这个功能扩 `CS2U_MAX_PARAMS`（除非选 §5.1 方案 A 并接受抬 `CS2U_MAX_ENTRIES`）。

## 10. 实施记录（1.0.12，2026-11-07）

### 10.1 四个待拍板问题的实际取舍

| 问题 | 决定 | 与任务书的关系 |
|---|---|---|
| `cs2feel_spread_tick_profile` 怎么进 | **方案 B：独立通道**。`FindConVar` + `SetConVarInt`，持久化在 `cs2unified.cfg` 的 **`env` 段**（不是新文件：同一份配置、同一次写盘、同一个 `.bak`，热重载能一起回填） | 与 §5.1 的推荐一致 |
| 要不要写 `sv_*` | **不写，永久**。`sv_maxupdaterate` 只出现在探测输出里并标注「本插件从不写」；verify 里有一条断言 `cs2u_env.sp` 中 `SetConVar*("sv_…")` / `ServerCommand(...sv_…)` **0 处** | 与 §5.2 一致 |
| 一键 = 直接改还是先预览 | **必须先预览**：`apply` 在没有新鲜预览（120 s）时被拒；预览后项数变化也会被拒（世界变了就不按旧 diff 写） | 与 §5.3 一致 |
| 30 tick / listen 的语义 | 见 10.2 的推荐表；实现里对 listen server **没有特殊分支**（`IsDedicatedServer` 只用于展示与理由文案），理由是“保守”已经由“never turn on, only turn off”覆盖 | 比 §5.4 更保守 |

### 10.2 推荐表（实现真相）

| 实测档 | spread 档位 | air_jump_speed | lowspeed_sustain | 说明 |
|---|---|---|---|---|
| 64 Hz（63.5–65.5） | **4**（强制 64） | 不动 | 不动 | 两者都在 64 tick 量过 |
| 60 Hz（57.0–63.5） | **3**（强制 60） | 1 → **0** | 1 → **0** | 没量过就不该留在“已开”状态 |
| 30 Hz（28.5–31.5） | **0（关）** | 1 → **0** | 1 → **0** | **“关”就是 30 Hz 的标定**（TV-45/TV-56 标的就是默认 ConVar），强行写 2 会覆盖操作者自己的 duck/air |
| 其它（含 100 Hz） | **0** | 1 → **0** | 1 → **0** | 未标定，不猜（TV-60 的限制） |

两条硬规则：

1. **只会建议“关”，不会建议“开”**。开 `air_jump_speed` 是玩法决定，不是环境决定。
2. **档位只在本机解析结果与实测档不一致时才提议**。例如 64 Hz + `档位 1（auto）`：auto 已经解析成 64，
   再写 4 只是无意义的落盘 —— 这种“看起来该改其实等价”的情况不产生 diff。

`lowspeed_sustain` 与 `duck_speed_min > 0` 的互斥（D9）**只警告**，不自动二选一（那是手感取舍）。

### 10.3 与任务书的偏差（都是刻意收窄）

| 任务书 | 实现 | 原因 |
|---|---|---|
| §6.1 列了 `CS2U_EnvSnapshotSave/Load` 落盘快照 | 只做**内存**快照（一次可撤销）+ `env` 段 | 跨重启保留“上上次”的快照会带来第二个真相来源；用户要的是“点错了能退回去”，一次足够 |
| §6.2 建议“复用 weapons 模式或做成 MOVE 普通行 + 二次确认菜单” | 复用 weapons 模式（第三个“代码拥有的三层页”） | 一页放得下 7 行：两条只读 + 详情/预览/应用/撤销 |
| 只提到探测与适配 | 多了一个 `sm_cs2u_env clear` | 应用后的 `env` 段除了 undo 没有别的移除方式；测试要能把服务器还原成“未适配” |
| §6.3 说 harness 要给 `Start-DsServer` 加 `-Tickrate` / `-NoTickMod` | 照做，并让 `Stop-DsServer` **总是**还原 `.vdf` | 套件崩溃不能把测试服永久留在 30 Hz |

### 10.4 实测

- 静态 **135/135**（新增 20 项），编译 **174,010 B / 0 error 0 warning**。
- 运行时 `tests\results\ci-env-3\env.md`：**54/54**，64 Hz 与 30 Hz 两轮。
- 顺带发现并修掉两个测试基础设施问题（写进 CHANGELOG）：
  1. `ACTION` 遥测写在 `addons\sourcemod\logs\L<日期>.log`，**不在** `console.log` ——
     1.0.11 的“被拒的值没有记 ACTION”是一条真空断言；
  2. RCON 的**监听端口在 `Host_NewGame` 期间会短暂关闭**（本机实测 5–15 s 窗口），
     旧 `Invoke-Rcon` 把连接异常当成“答案”返回，于是“服务器正在载图”被误报成“功能坏了”。
     现在按 `### <cmd>` 标记判定成功，并在重试前先探测端口。
