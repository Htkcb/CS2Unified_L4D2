# 02 · 两级菜单、鉴权与 menu.cfg（v1.0.5）

> 权威来源：`src\cs2u_menu.sp`（两级菜单 + 7 个 handler）、`src\cs2u_layout.sp`（menu.cfg 解析/校验/默认布局）、`src\cs2u_auth.sp`（身份解析）、`src\cs2u_params.sp`（39 个受管参数与中文标签）、`src\cs2u_core.sp`（命令/权限入口）。
> 菜单的**客户端点选/翻页观感**仍未在真人客户端验证（见 §10）。

---

## 1. 入口

| 入口 | 行为 | 权限 |
|---|---|---|
| `!cs2u` / `!cs2u_menu` | SourceMod 映射到 `sm_cs2u` / `sm_cs2u_menu`（`RegConsoleCmd`），插件内再判身份 | 见 §5；拒绝时回“权限不足”并记 `AUTH-DENIED` |
| `!menu` / `!c2u` | 默认不拦截；仅 `cs2u_menu_chat_alias 1` 时由 `OnClientSayCommand` 接管 | 同上 |
| `sm_cs2u`（控制台） | 服务端控制台调用 → 提示 client-only | — |
| `!admin` | **不接管**，仍是 SourceMod 自带 Admin Menu | — |

`sm_cs2u` 故意注册为 `RegConsoleCmd`，这样非管理员收到“权限不足”而不是 `Unknown command`。真正的判定在 `Cmd_Menu` → `CS2U_AuthCheck`。

---

## 2. 布局契约

- 每页固定 **7 个内容行**（不足补 `ITEMDRAW_DISABLED` 空行），`#8` 返回/上一页，`#9` 下一页。
- `MENU_NO_PAGINATION` + 手写分页；`SetMenuExitButton` 在 `SetMenuPagination` **之后**调用（切分页会清 exit 标志）。
- 分页菜单只允许 `DEFAULT` / `DISABLED` 两种样式；分组标题因此只能是 `ITEMDRAW_DISABLED` 行，不使用分隔线/空白样式。
- **最多 2 层**：根 → 1 级子页；值不再开第三层，参数行点击即循环到下一个候选值。
- **7 个页面上下文**：`root` / `presets` / `feel` / `move` / `visual` / `status` / `config`。没有 `simple` / `spresets` / `diy0` / `diy1` / `val.*` / `tier` / `camera` / `recoil` / `bmode`。
- 分组标题不会单独落在页面末尾：`CS2U_PackPages` 若发现某页最后一行是标题，就把边界回退一行，标题移到下一页开头。
- 客户端选择后**重建** Menu（不原地重排；避免 SourceMod 菜单项索引漂移）。

## 3. 菜单树

### 3.1 根菜单（两个视图）

```text
常用视图（6 行，1 页）
CS2Unified v1.0.5
预设: cs2_full ｜ 手感 开 ｜ 移动 开 ｜ 曳光 关
├─ nav:presets  预设与模式 / Presets
├─ nav:feel     手感 / Feel
├─ nav:move     移动与受伤 / Movement & Injury
├─ nav:visual   视觉与准星 / Visual & Crosshair
├─ nav:status   状态 / Status
└─ adv.on       高级模式 / Advanced mode [ROOT]

高级视图（7 行，1 页；仅 ROOT）
├─ nav:presets / nav:feel / nav:move / nav:visual
├─ nav:status   状态与诊断 / Status & Diagnostics
├─ nav:config   配置与保存 / Config & Save [ROOT]
└─ adv.off      退出高级模式 / Exit advanced
```

- 两个视图的并集只有 7 个不同顶层项（`config` 仅高级出现），不是两套菜单。
- `admin` 级管理员只看得到 feel / move / visual / status（预设/配置/DIY/诊断全是 ROOT）。
- 高级模式是**会话内**状态，默认取 `menu.cfg` 的 `advanced_default`；不写盘。

### 3.2 预设与模式（`presets`）

```text
常用（ROOT）：7 行，1 页
├─ preset:<idx>  cs2_full [active]
├─ CS2 完全仿真（cs2_full）      ← 默认：TR-40 + 滑行 0.45
├─ CS2 竞技移动（cs2_competitive）
├─ CS2 匹配（cs2_matched） / CS2 原生分离（cs2_split）
├─ CS2 匹配 + 曳光（cs2_tracer） / 仅移动（movement_only） / 原版（vanilla）
└─ DIY 高级 / DIY 简单（预设菜单内）
（行文本 = 中文名（内部 key），`sm_cs2u_preset` 仍只认内部 key）
└─ （顺序由 menu.cfg 的 order.presets 决定）

高级（ROOT）：第 2 页追加 DIY
├─ 「DIY 自定义」标题
├─ diy.apply.0 / diy.save.0
└─ diy.apply.1 / diy.save.1
```

### 3.3 手感（`feel`，3 页）

```text
├─ 「结构」
│  ├─ act:recoil      后坐结构：匹配 / 分离 / 爬升（点此切换，写 7 个受管值 + 一次持久化；切换后 cs2u_bmode 回自动）
│  ├─ act:bmode       弹道模式：策略（自动/单人·TR-40/多人）+ 实际结构 + 相机/弹道比例（点此切换）
│  ├─ act:clientinfo  客户端 aim-sync 装法（聊天）
│  └─ act:facts       实测数字（聊天）
└─ 「参数」
   └─ cyc:0..10       总开关、后坐/弹道/散布参数（行内循环）
```

`cs2u_bmode` 由 `act:bmode` 代表，不单列参数行；仍可经循环行修改。  
行文本同时给出「策略」和「实际结构」：策略是 `cs2u_bmode`，实际结构从 7 个 cvar 读回（匹配/分离/爬升）+ `相机/弹道` 比例；两者不一致时（例如预设覆盖了结构）会直接显示「实际 …」。控制台 `sm_cs2u_set cs2u_bmode <0-3>` 现在也会应用 7 个结构值，与菜单行等价。

```text
├─ 「滑行」（实测最高频）
│  ├─ act:slide_tier  档位：0.20 / 0.40 / 0.45 / 0.50（点此切换，选中即开启滑行）
│  ├─ cyc:18          蹲下滑行
│  ├─ cyc:19          客户端滑行
│  └─ cyc:21          滑行最低启动速度
├─ 「受伤减速」
│  └─ cyc:27..33      7 个受伤参数
├─ 「水面减速」（1.0.10）
│  ├─ cyc:34          水面减速（开关）
│  └─ cyc:35          水面减速强度（眼深，0.35 = 踝 0.883 / 腰 0.767 / 眼 0.650）
└─ 「速度与模型」
   └─ cyc:12..17,20,22..26（含 ROOT: 23/24/26）
└─ 「详细移动数值」（1.0.11）
   └─ act:weapon_speeds  详细移动数值：18 件武器（点此进入）
└─ 「环境适配」（1.0.12）
   └─ act:env_adapt  环境适配：64 Hz / 专用服 / 有建议待确认（点此进入）
```

`cs2movement_crouch_slide_time`（idx20）由 `act:slide_tier` 代表。

> 旧 `menu.cfg`（1.0.10 之前安装、部署时 onlyIfMissing 不会覆盖）不含 `cvar:cs2movement_water_*`，
> 加载时由 `CS2U_OrderAppendMissing()` 追加到该页末尾：参数一定可见，位置可能落在「速度与模型」之后。
> `act:weapon_speeds` 同理（这个 act 在代码里被列为“必须存在”，旧配置也会被补上）。

#### 3.4.1 详细移动数值（`weapons`，3 页）——唯一的三层页

```text
├─ 「各武器移动速度（u/s，* = 已改）」
│  ├─ wpn:0   M16 步枪：215
│  ├─ wpn:1   AK-47：215
│  ├─ …        共 18 行（rifle×4 / smg×3 / pistol×2 / sniper×4 / shotgun×3 / melee×2）
└─ 「恢复」
   └─ wpn:reset  恢复默认数值（18 件，立即写盘）
```

- 点某一行 → 关菜单、聊天栏提示当前值 → **直接在聊天栏输入新速度**（50–1000）。
  60 秒内有效；输入「取消 / cancel / q」放弃；非数字或越界会在聊天栏说明原因且不写入。
  写入成功后自动重开本页，改过的行带 `*`。
- 每次修改**立即重写** `addons\sourcemod\configs\cs2movement_weapons.cfg`（tmp → .bak → rename），
  所以换图、`sm_cs2movement_reload` 都不会把它改回去。
- 只有 ROOT 能进（与 `cs2movement_maxspeed` / `weapon_speed_mode` 同级）。`#8/#9` 翻页、`#8` 第一页回移动页。
- 这一页**不是** `CS2U_CTX_*` 上下文：`menu.cfg` 不能给它排序，它只有移动页那一个入口键
  （`act:weapon_speeds`）。控制台等价物是 `sm_cs2u_weapons`。

#### 3.4.2 环境适配（`env`，1 页）——按本机 tick 对齐

```text
├─ 「本机环境（只读）」
│  ├─ env.info.host      64.00 Hz ｜ 专用服 ｜ 31 槽 ｜ 0 人        （disabled 行）
│  └─ env.info.profile   spread 强制 64（4） → 建议 强制 64（4）    （disabled 行）
├─ env.detail   查看完整探测（聊天输出，含每项来源）
├─ env.preview  预览适配：1 项（点此列出 旧 → 新）
├─ env.apply    确认应用：1 项（须先预览，120 秒内有效）
└─ env.undo     撤销上次适配：1 项 / 无快照
```

- 只有 ROOT 能进，而且**行本身**对 GENERIC 管理员不渲染（E-8：看不到，而不是点了被拒）。
- `preview` 只打印 `旧 → 新` 与理由，**不改任何值**；`apply` 只写预览里列出的项，全部成功或全部回滚；
  预览超过 120 秒、或预览之间的值被人改动（项数变化）都会拒绝应用。
- `undo` 把上次适配覆盖的值逐字写回，并把 `cs2unified.cfg` 的 `env` 段一起还原。
- 这一页同样**不是** `CS2U_CTX_*` 上下文，入口键只有一个 `act:env_adapt`。
  控制台等价物是 `sm_cs2u_env [status|preview|apply|undo|clear]`。

### 3.5 视觉与准星（`visual`，2 页）

```text
├─ 「曳光」     cyc:36 / 37 / 38
└─ 「相机（客户端 Left4Neko）」
   ├─ act:camera_detect  检测我的 Left4Neko（QueryClientConVar）
   ├─ act:camera_zero    推荐 0：相机冻结（直接 ClientCommand 下发）
   ├─ act:camera_off     关闭：1.0（直接 ClientCommand 下发）
   └─ act:camera_note    说明：代设只对本次会话生效
```

服务器**不写**任何相机 cvar；`camera_zero`/`camera_off` 用 `ClientCommand` 代设客户端
`l4n_view_punch_scale`（只对本次会话生效，退出游戏可能写回 `config.cfg`），并用
`QueryClientConVar` 回读确认。相机冻结后，climb 的 `1.30` 倍弹道会在**静止准星**上方
明显爬升（AK 满自动约 6.8°，远大于相机 1.0 时的 1.2°）。

## 4. info id 契约

| 形态 | 生成 | 消费 | 说明 |
|---|---|---|---|
| `nav:<ctx>` | 根 | `MenuHandler_Root` | 只允许 7 个 ctx 名 |
| `cyc:<idx>`（emit 时追加 `:<page>`） | 参数行 | `CS2U_HandleSelect` | 循环候选值 |
| `act:<id>`（追加 `:<page>`） | 动作行 | `CS2U_HandleSelect` | id 见 §3 |
| `preset:<idx>`（追加 `:<page>`） | 预设行 | `MenuHandler_Presets` | `idx` 是运行期预设索引 |
| `diy.apply.<w>` / `diy.save.<w>`（追加 `:<page>`） | DIY 行 | `MenuHandler_Presets` | `w`=0 高级 / 1 简易 |
| `wpn:<idx>` / `wpn:reset`（追加 `:<page>`） | 武器速度页 | `MenuHandler_Weapon` | 1.0.11 |
| `env.<action>`（追加 `:<page>`） | 环境适配页 | `MenuHandler_Env` | 1.0.12；`action` ∈ `detail/preview/apply/undo` |
| `adv.on` / `adv.off` | 根 | `MenuHandler_Root` | 切换视图 |
| `prev:<ctx>:<page>` / `next:<ctx>:<page>` | #8/#9 | `CS2U_MenuPager` | 3 段 `:` |
| `back` | #8 首页 | 各 handler | 根关闭；子页回根 |
| `hdr` / `pad` | 分组标题/空行 | 无 | `ITEMDRAW_DISABLED` |

## 5. 鉴权（SteamID 列表 > 管理员组）

### 5.1 解析顺序（`CS2U_AuthResolve`）

```text
client == 0                    → source=console, tier=root
SteamID 在 auth.steamids       → source=steamid, tier=<条目>
在 auth.groups 的组内          → source=group:<名>, tier=<条目>
都没有                         → deny
auth 段缺失/为空               → 回退 SourceMod flag（source=flag）
```

- 同时命中 SteamID 与组：**SteamID 为准**，tier 取 SteamID 条目；每图每客户端写一次 `AUTH-CONFLICT`（含两边 tier 与 `chosen=steamid`）。
- 组判定用 `GetUserAdmin` / `GetAdminGroupCount` / `GetAdminGroup` + `FindAdmGroup`，组名由 `menu.cfg` 的 `auth.groups` 给出。
- tier：`root` 可进高级视图、可执行 ROOT 动作；`admin` 只用常用视图与 ADMIN 参数。

### 5.2 日志

| 标签 | 时机 | 关键字段 |
|---|---|---|
| `AUTH-OK` | 每次成功打开菜单 | client / steamid / source / tier |
| `AUTH-DENIED` | 拒绝（同一客户端 10 秒内只记 1 条） | client / steamid / name / where |
| `AUTH-CONFLICT` | SteamID 与组同时命中 | client / steamid / 两边 tier / chosen |
| `AUTH-RELOAD` | 重载 menu.cfg | steamids / groups / strict |

### 5.3 拒绝流程

- 入口：`Cmd_Menu` → `CS2U_AuthCheck` → 失败则聊天“权限不足 / Access denied — 你不在管理员名单中。”，**不创建 Menu**（客户端留在游戏）。
- 菜单内：每个 handler 先 `CS2U_AuthCheck`；权限被撤/陈旧选择 → 提示 + `AUTH-DENIED`，不进入下一步。
- handler 内 ROOT 动作再 `CS2U_AuthRequire` 一次（不信任 info id）。
- **边界**：菜单入口与可见性以 `auth` 为准；`sm_cs2u_*` 控制台命令仍由 SourceMod flag 控制（命令是独立入口）。两套源不一致时启动会写 `AUTH-WARN`（生成脚本默认保持对齐）。

## 6. menu.cfg 与热重载

### 6.1 位置与结构

`addons/sourcemod/configs/cs2unified/menu.cfg`（随包 `configs\cs2unified\menu.cfg`，部署时仅在目标不存在时复制）。

```text
"CS2UnifiedMenu"
{
    "schema" "1"
    "menu"
    {
        "advanced_default" "0"
        "confirm_destructive" "0"
        "telemetry" "1"
        "perm.config" "root"      // root | hidden
        "perm.diy" "root"
        "perm.diag" "root"
        "visible.basic" "presets,feel,move,visual,status"
        "order.presets" "preset:cs2_full,preset:cs2_tracer,..."
        "order.feel"    "act:recoil,act:bmode,...,cvar:cs2feel_enable,..."
        "order.move"    "act:slide_tier,cvar:cs2movement_crouch_slide,..."
        "order.visual"  "cvar:cs2u_tracer_enable,...,act:camera_detect,..."
        "order.status"  "act:status_full,...,act:diag_l4n"
        "order.config"  "act:save,...,act:menu_reset"
    }
    "auth"
    {
        "priority" "steamid"      // 只接受 steamid
        "steamids" { "0" "STEAM_1:0:xxx root" }
        "groups"   { "0" "Full Admins root" }
    }
}
```

### 6.2 可配置项（20 项上限）

`menu` 段直接键 + `auth` 段直接键（priority/steamids/groups）合计 ≤ 20；名单条目本身不计入，但另设上限（SteamID 64 / 组 16）。随包模板是 13 项（无 auth）或 16 项（含 auth）。

校验规则（任一不满足 → 整段回退默认 + `MENU-CONFIG-FALLBACK`，auth 清空回 flag）：

- `perm.config` / `perm.diy` / `perm.diag` 只接受 `root` | `hidden`；写 `admin` 等其它值会被拒绝（1.0.5 起）。`visible.basic` 只接受 `presets,feel,move,visual,status`；`config` 是高级视图专属，写进去会被拒绝，而不是静默无效。
- `order.*` 的 `act:` 必须属于该页上下文；`cvar:` 必须是已注册的受管参数；`preset:` 必须是当前存在的预设。
- `auth.priority` 只接受 `steamid`；单条 auth 格式错只跳过该条，不触发整段回退。

### 6.3 校验与回退（fail-closed）

| 情况 | 结果 |
|---|---|
| 文件不存在 | 内置默认布局，`MENU-CONFIG-DEFAULT`，不算错误 |
| parse 失败 | 整段回退默认；`MENU-CONFIG-FALLBACK reason=parse`；`g_sMenuCfgError` 供状态页显示 |
| `order.*` 未知/重复/空/超过 40 项 | 拒绝并回退；reason 带 key 与坏 id |
| 可调键 > 20 | 拒绝并回退；`reason=too_many_keys N>20` |
| `auth.priority != steamid` | 拒绝并回退；auth 清空 → flag 模式 |
| 单条 auth 格式错 | 跳过该条 + `MENU-CONFIG-AUTH-SKIP`，其余生效 |
| 校验通过 | `MENU-CONFIG-OK initial=... keys=... steamids=... groups=...` + `AUTH-RELOAD` |

回退时 **auth 也清空**（回到 flag），避免坏文件把全部管理员锁在门外。管理员下次打开菜单会收到一行提示（`CS2U_MenuCfgNotify`）；手动 reload 时直接回显给执行者。

### 6.4 热重载

`sm_cs2u_reload` 同时：
1. 重载 `cs2unified.cfg`（参数/预设 + 应用 settings）；
2. 重载 `menu.cfg`（顺序/可见性/权限/鉴权）。

新布局在**下一次打开**菜单时生效；已打开的菜单不中途换页。`act:reload` 与 `act:menu_reset` 走同一条路径。

### 6.5 生成鉴权名单

不运行期读 `admins_simple.ini`（避免双源漂移）。用一次生成脚本：

```powershell
powershell -File tools\gen_menu_auth.ps1 `
  -AdminIni "<DS_DIR>\left4dead2\addons\sourcemod\configs\admins_simple.ini"
```

它把 `"STEAM_x" "99:z"` 映射为 `STEAM_x root`（无 z 映射为 admin），并保留 `Full Admins` 组映射。

## 7. 反馈、重开与遥测

| 操作 | 成功反馈 | 失败反馈 | 之后停在哪 |
|---|---|---|---|
| 参数行循环 | `OK: <cvar> = <value> (persisted)` | `Rejected: <原因>` / `persistence failed` | 同一页 |
| 后坐结构切换 | 结构说明 + 客户端 ratio 提示 | `rejected:` / 写盘失败 | 手感页 |
| 弹道模式切换 | 模式说明 + 客户端要求 | `rejected:` | 手感页 |
| 滑行档位 | `蹲下滑行：<tier> s（已开启并保存）` | `保存失败：<原因>` | 移动页 |
| 预设应用 | `Applied preset '<name>' (<N> parameters); persisted` | `Preset failed:` / 权限拒绝 | 预设页 |
| 配置动作 | 见 §3.7 | `<动作> failed:` | 配置页 |
| 高级模式切换 | 直接切视图 | — | 根（同页） |
| 鉴权失败 | — | `权限不足 / Access denied` | 不打开菜单 |

- `MENU-SELECT`（`menu.telemetry 1`）：每次选择写 ctx / info / steamid / tier，作为后续 CTR 排序数据。
- 菜单 30 秒无操作自动关闭（`Display(client, 30)`）。
