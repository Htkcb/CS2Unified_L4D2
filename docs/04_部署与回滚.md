# 04 · 部署与回滚

> 权威来源：`tools\build.ps1`、`tools\deploy.ps1`、`tools\uninstall.ps1`、`_backup\<时间戳>\install-manifest.csv`、`tests\results\runtime-smoke.md`。
> 所有目标路径都相对于 `left4dead2\`；默认目标根 `<DS_DIR>`（脚本参数 `-GameDir`）。

## 1. 构建前置

| 前置 | 要求 | 说明 |
|---|---|---|
| `spcomp.exe` | SourceMod **1.12** 编译器 | `build.ps1` 依次在：`-CompilerPath` → `<DS_DIR>\left4dead2\addons\sourcemod\scripting\spcomp.exe` → `..\Left 4 Dead 2\left4dead2\addons\sourcemod\scripting\spcomp.exe` → `PATH` 中查找 |
| 头文件 | `<spcomp 目录>\include\sourcemod.inc` 存在 | 否则 `throw "SourceMod include directory not found"`；可用 `-IncludePath` 覆盖 |
| 源文件 | `src\cs2unified.sp` 及其 `#include` | 9 个生成文件必须已由 `sync_sources.ps1` 产出 |
| 上游（仅同步时需要） | `..\CS2FeelVScript_L4D2\plugin_src`、`..\CS2Movement_L4D2.public\scripting` | `sync_sources.ps1` 会校验两个目录存在 |

```powershell
cd <REPO_ROOT>

# 全量：同步 → 编译（严格告警）
powershell -ExecutionPolicy Bypass -File .\tools\build.ps1 -Sync -StrictWarnings

# 显式指定编译器
powershell -ExecutionPolicy Bypass -File .\tools\build.ps1 -CompilerPath '<DS_DIR>\left4dead2\addons\sourcemod\scripting\spcomp.exe'
```

产物固定为 `build\cs2unified.smx`（约 **104–128 KB**，最新 127,985 B）。`build.ps1` 末尾会打印实际字节数与 SHA256；**不要把它写死进文档或部署脚本**——`spcomp` 产物含非确定内容，同一源码两次构建可能大小差 ±1 B、哈希每次都不同。

编译成功判据（`verify.ps1` 第 2 项）：`0 error` 且 **`-StrictWarnings` 下 0 warning**。

## 4. 为什么要停用旧插件

`cs2feel_core.smx` 与 `cs2movement.smx` 和合并产物**注册同一批 ConVar 与命令**：

- 重复 `CreateConVar("cs2feel_*")` / `CreateConVar("cs2movement_*")` → SourceMod 日志出现重复 ConVar 警告，两个插件各写一份值，行为不确定；
- 重复 `RegAdminCmd("sm_cs2feel_*")` / `sm_cs2movement_*` → 后加载者覆盖命令归属，`sm_cs2u_diag` 里看到的模块状态与实际执行的代码可能不是同一份；
- 两套 DHooks detour / SDKHook 同时挂 → 速度被写两遍，无法归因。

所以 `deploy.ps1` 默认把两者移入 `plugins\disabled\`（不是删除），并由 `uninstall.ps1` 在回滚时移回。`-KeepLegacy` 只用于“故意对照”的场景，日志会明确警告。

`-DisableProbes` 额外停用 `cs2f_mv3.smx` / `cs2f_aimdebug.smx`：它们是上游的**测试探针**（MV3 视觉/瞄准调试），不属于生产插件；保留会额外打日志、挂 hook。是否停用不影响合并插件功能。

## 5. 备份与清单

每次 `deploy.ps1` 运行（非 `-DryRun`）：

```text
<项目>\_backup\<yyyyMMdd-HHmmss>\
├─ addons\sourcemod\plugins\cs2unified.smx      # 仅当目标原本存在
├─ addons\sourcemod\gamedata\l4d2_cs2feel.txt
├─ ...
└─ install-manifest.csv
```

- 备份目录结构**镜像** `left4dead2\` 下的相对路径；只备份“本次会被覆盖/移动”的文件，不是整服快照。
- 清单列：`action, relpath, backup, bytes, sha256`；`action` 只有 `copy` / `disable` 两种。
- **run manifest 每完成一个动作就写一次**（`Write-RunManifest`）：中途失败/被杀也留下“已经改到哪一步”的撤销记录（H-02 修复）。
- **`_backup\project-manifest.csv`**：每次部署把本次清单合并进去，**每个路径保留第一次备份**（绝对路径）。这是“项目引入前”的权威还原点；重复部署不会用它覆盖掉真正的原始备份。
- 旧插件已被上一次部署停用时，本次仍会写一条 `disable` 行（控制台打印 `ALREADY-DISABLED`），使默认卸载能正确移回。
- `bytes`/`sha256` 记录的是**本次从项目复制过去的源文件**（`copy`）或**被移动走的文件**（`disable`）。它可用于核对“装上去的是不是这一份”，**不能**用于核对“恢复后的备份是否与原始一致”（`uninstall.ps1` 也不做这种校验）。
- 运行期生成物 `configs\cs2unified\cs2unified.cfg` 与 `cfg\sourcemod\cs2movement.cfg` 仍不在 manifest 里；但 `uninstall.ps1` 会额外检查 `configs\cs2unified`：**只有当目录里只剩 `cs2unified.cfg` / `cs2unified.cfg.bak` 时才删除该目录**，有其它文件则 `KEEP`。

实测的清单（`_backup\`）：

| 目录 | 内容 |
|---|---|
| `20261031-174014` | **10 条 `copy` + 4 条 `disable`**：首次完整部署（含停用旧插件与探针）。`copy` 里 `cs2unified.smx` 为 **104,419 B**；`disable` 为 `cs2feel_core.smx`（49,201 B / `03F069C5…`）、`cs2movement.smx`（**38,228 B** / `C2C281ED…`，当时线上 0.4.8，历史备份）、`cs2f_mv3.smx`（8,497 B）、`cs2f_aimdebug.smx`（16,019 B） |
| `20261031-175513` / `-175753` | 各 **10 条 `copy`**（无 `disable`，旧插件已在上一次移走）：`cs2unified.smx` 分别为 105,558 / 105,557 B |
| `20261031-180836`（H 修复后） | 第二次部署：记录 **4 条 `ALREADY-DISABLED`** 的 `disable` 行；run manifest `copy=10 / disable=4`；`project-manifest.csv` 保留首次备份的绝对路径 |
| `20261031-181217` / `-181334`（M 修复后） | `cs2unified.smx` 106,488 B |
| `20261031-191143` / `-191307` / `-191445`（`cs2_full` 后） | 113,273 / 113,566 / 113,592 B |

| `20261031-192421`（movement 0.4.8 后） | 115,946 B |

## 6. 卸载与回滚

```powershell
# 默认 DRY-RUN：只打印
powershell -ExecutionPolicy Bypass -File .\tools\uninstall.ps1

# 执行：默认优先使用 _backup\project-manifest.csv（每个路径的首次备份）
powershell -ExecutionPolicy Bypass -File .\tools\uninstall.ps1 -Apply

# 只撤销某一次部署（用该次的时间戳目录）
powershell -ExecutionPolicy Bypass -File .\tools\uninstall.ps1 -Apply -BackupDir .\_backup\20261031-180836

# 换一个服务器根
powershell -ExecutionPolicy Bypass -File .\tools\uninstall.ps1 -Apply -GameDir D:\l4d2ds
```

默认目录选择（H-02 修复后）：

1. 存在 `_backup\project-manifest.csv` → **用它**（每路径首次备份，等价于“项目引入前”）；
2. 否则退回“`_backup` 下 `LastWriteTime` 最新的目录”。

逐行语义：

| 清单 action | 卸载动作 |
|---|---|
| `copy` | 删除安装到目标的文件；若 `backup` 非空且备份存在 → 把备份复制回原位（恢复部署前版本）；`backup` 为空 → 仅删除 |
| `disable` | 把 `plugins\disabled\<name>` 移回 `plugins\<name>`；若 `disabled` 里没有 → 尝试用备份复制回去；两者都没有 → `WARN cannot re-enable` |
| 其它 | `WARN unknown action` |

额外清理：`addons\sourcemod\configs\cs2unified` 只在**目录内全部文件都属于项目**（`cs2unified.cfg` / `cs2unified.cfg.bak`）时删除，否则打印 `KEEP`（保护管理员自己放进去的文件）。

注意：

- 回滚**只**处理清单里列过的文件；`cfg\sourcemod\cs2movement.cfg`（AutoExecConfig 生成）不在清单内，不会被清理。
- **默认 = 项目引入前**（project-manifest）；**`-BackupDir` = 只撤销那一次部署**。两者不是一回事：多次部署后若想“彻底卸载”却传了最新时间戳目录，会得到中间状态。
- `_backup\<时间戳>\` 里的备份**不会被删除**，可重复回滚；确认无误后手工清理。
- 回滚后必须**重启 srcds**：`.smx` 的加载/卸载、`disabled\` 的移回都要在进程启动时生效。
- 卸载脚本不做哈希校验；核对恢复结果请自己 `Get-FileHash` 与备份文件比较。

实测还原结果：

- 单次完整清单（`_backup\20261031-174014`，`tests\results\runtime-smoke.md` §6）：`sm plugins list` 恢复 **90 项**，包含 `CS2Feel (0.5.7-m11)`、**`CS2Movement (0.4.8)`**、`CS2F aim debug`、`CS2F M-V3`；`cs2unified.smx` 移除；5 个被覆盖文件哈希与备份 **逐项 MATCH**。
- 重复部署后默认卸载（§9，H-02 复验）：不传 `-BackupDir`、使用 `project-manifest.csv` **15 行**；`cs2unified.smx` 移除、4 个 legacy（`cs2feel_core` / `cs2movement` / `cs2f_mv3` / `cs2f_aimdebug`）回位、`configs\cs2unified` 删除；`cs2unified.smx=False`、`legacy4=4`、`configs\cs2unified=False`。

## 7. 数据层 VPK 与双端一致性

| 项 | 值 |
|---|---|
| 文件 | `addon\cs2feel_r2_plugin.vpk`，**85,318 B** |
| SHA256 | `D7C43E5CA9BC255A52B0CE1BE149A8C254C9017AF72D9E4B6A36B975D364C7BC`（与 `..\CS2FeelVScript_L4D2\addon\cs2feel_r2_plugin.vpk` **完全一致**） |
| 内容 | VPK v1；tree 含 `addoninfo` + **13** 个 `scripts\weapon_*.txt` |
| 安装位置 | 服务器与客户端都是 `left4dead2\addons\cs2feel_r2_plugin.vpk` |
| 层定位 | 数据层（`addoninfo.txt` 自述 `addonversion 0.5.0`，只拥有 7 个扩散键；其余键与 `CS2Feel_L7_WeaponScripts_v1.6.2` 逐字节相同） |

三条硬约束（来自 VPK 内 `addoninfo.txt`，不是本项目发明）：

1. `cs2feel_spread_mode` 必须保持 **0**（默认）；不要在该数据层启用时打开插件的 spread 模块，否则扩散有两个来源。
2. **不要**同时启用 `cs2feel_vscript_pure.vpk`：两者覆盖同一批 `scripts\weapon_*.txt`。
3. VPK 是**加载期资产**：替换后必须重启游戏/服务器；SourceMod 无法热切换，统一层的预设也只管运行时 ConVar。

双端一致性：客户端与服务器的 VPK 必须同版本；插件（`cs2unified.smx`）与 VPK 也应视为**同一发布单元**——数据层决定扩散形状，插件决定后坐力/弹道/移动。混搭会出现“同一套参数、不同弹道”的不可复现现象。

## 8. 升级流程

### 8.1 常规升级（有源码）

```powershell
# 0) 停服
# 1) 更新只读上游 → 重新生成 src\
powershell -ExecutionPolicy Bypass -File .\tools\sync_sources.ps1
# 2) 63 项静态验收
powershell -ExecutionPolicy Bypass -File .\tools\verify.ps1
# 3) 构建
powershell -ExecutionPolicy Bypass -File .\tools\build.ps1 -StrictWarnings
# 4) 看计划
powershell -ExecutionPolicy Bypass -File .\tools\deploy.ps1 -DryRun
# 5) 部署（自动备份）
powershell -ExecutionPolicy Bypass -File .\tools\deploy.ps1
# 6) 起服 → 按 docs\05 §5 做运行时冒烟
# 7) 记录：本次 _backup 时间戳、build 输出的字节/哈希、三方版本日志
```

失败回退：`uninstall.ps1 -Apply -BackupDir .\_backup\<本次时间戳>` 然后重启。

### 8.2 movement 基线与 0.5.2（injury + 滑行参数受管）

本项目已整合 `CS2Movement_L4D2.public` 的当前源码（movement **0.5.2**，2026-11-01 本地 bump；上一发布 tag 为 **v0.5.1**），线上二进制仍是 **0.5.1**。**0.4.5 → 0.5.2 的差异已经纳入**，不再需要“先取得新源码”的特殊流程。

- 0.5.1 新增 `cs2movement_injury.sp`（7 个 `cs2movement_injury_*` ConVar）；`cs2movement.sp` 的 include 链变成 5 个 movement 文件。
- **0.5.2 只改出厂默认与接口**：`crouch_slide_time` 0.10 → **0.20**（CS2 等价），并把它与 `crouch_slide_min_speed` 暴露给统一层（受管参数）；滑行曲线/物理未改，未新增 ConVar。
- 0.4.8 的 `cs2movement_maxspeed` 语义保留：per-player 上限钳制、默认 1000，不再写全局 `sv_maxspeed`；内置预设统一写 1000。
- `configs\cs2movement.cfg` 已同步 0.5.2：包含 injury 七项（`enable 1 / mode 1 / base 220 / speed 132 / health 0 / temp_health 1 / adrenaline 1`）、`cs2movement_maxspeed 1000` 与 `crouch_slide_time 0.20`。
- 旧的 `..\CS2Movement_L4D2`（0.4.5）与 `..\CS2Feel_L4D2\scripting`（m10）**不再使用**；`sync_sources.ps1` 已指向 `.public` 目录。
- 若自行把上游换回旧 0.4.5/0.4.8，合并产物会与线上 0.5.1 不一致；不要混用两套 movement 二进制。

### 8.3 只换数据层 VPK

1. 停服；
2. 用同版本发布包的 VPK 替换 `addons\cs2feel_r2_plugin.vpk`（客户端同步替换）；
3. 起服，确认 `addoninfo` 里声明的 7 个键与插件侧 `cs2feel_spread_mode 0` 不冲突；
4. 不需要改 `cs2unified.cfg`（预设里没有数据层字段）。

### 8.4 打包发布（`tools\package.ps1`）

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\package.ps1
# 产出：dist\CS2Unified_L4D2-v1.0.1-<日期>.zip（+ 同名 .sha256）
```

- 包内含：**可直接覆盖到服端的 `left4dead2\` 树**（`.smx`、gamedata、cs2feel 配置、`cs2movement_weapons.cfg`、数据层 VPK）、`deploy.ps1` / `uninstall.ps1`、`docs\`、`README.md`、`INSTALL.md`、`LICENSE`、`NOTICE`、`client\`（玩家侧可选文件，见 §11）；
- 生成后附带 SHA256 校验文件，便于分发时核对；
- 打包**不**替代本文件的部署流程：仍然要先停服、备份、`uninstall.ps1 -Apply` 回滚可用。

## 9. 远程执行（RCON）

DS 自带的 `<DS_DIR>\_rcon.ps1` 把 `EXECCOMMAND` 发成 type 3（AUTH），服务端回 `id=-1` 且**不执行命令**。本项目的 `tests\rcon.ps1` 使用正确协议（AUTH=3、EXECCOMMAND=2、AUTH_RESPONSE=2、RESPONSE_VALUE=0），实测可用：

```powershell
.\tests\rcon.ps1 -Server <DS_HOST> -Port 27016 -Command 'sm_cs2u_status'
.\tests\rcon.ps1 -Server 127.0.0.1 -Port 27016 -Command 'sm plugins list','sm_cs2u_status'
```

密码用 `-Password` 传入，或设置环境变量 `CS2U_RCON_PASSWORD`（未提供时报错退出）。`-ReadTimeoutMs` 默认 1500。

## 10. 常见失败与排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `COPY` 失败 / 文件被占用 | 服务器还在运行 | 停 `srcds` 后重跑；`.smx` 被加载时无法覆盖 |
| 日志有重复 ConVar / 命令归属混乱 | 旧 `cs2feel_core.smx` / `cs2movement.smx` 仍在加载 | 确认 `plugins\disabled\` 里有它们；`sm plugins list` 不应同时出现旧插件与 `cs2unified` |
| `[CS2Feel] INACTIVE ... SIG-ERROR` | gamedata 缺失/游戏更新导致签名失配/Linux | 重新扫描签名；确认是 Windows 服；见 `docs\06` L4 |
| movement 只有全局 `sv_*` 生效 | 缺 DHooks 或 `cs2movement.txt` 签名失配 | 装 DHooks；重扫签名；`sm_cs2u_diag` 看模块状态 |
| `config rejected (...)` | 配置值越界/结构缺失/截断 | 看 `sm_cs2u_status` 的 `config error`；用 `.bak` 或仓库默认文件恢复 |
| `sm_cs2u` 在服务端控制台无输出菜单 | 设计如此（client-only） | 用 `sm_cs2u_status` / `sm_cs2u_preset` 等命令 |
| 换图后参数被改回 | ①改值时持久化失败（提示 `but persistence failed`，内存已改但磁盘是旧值，见 `docs\06` L15）；②`server.cfg`/`cs2movement.cfg` 后执行覆盖 | 修磁盘权限/空间后重试；确认 `cs2u_enable 1`；看日志 `PERSIST-APPLY` |
| RCON 命令无回显 | 用了 DS 自带的 `_rcon.ps1` | 改用 `tests\rcon.ps1` |

## 11. 客户端一半：aim-sync（可选；随包 `client\`）

服务器侧的「后坐结构」两档（匹配 / CS2 原生分离）只靠服务端就完整生效：子弹、命中、服务器弹道都不依赖客户端。**客户端这一半是可选的**，只决定“可见弹孔跟不跟随分离”。

| 项 | 值 |
|---|---|
| 随包文件 | `client\cs2feel_aimsync.ini`（Left4Neko 插件 `cs2feel_aimsync.dll` 的配置）；同目录还有 `client\cs2u_client_l4n.cfg`（相机 / 准星分离片段，见包内 `INSTALL.md`） |
| 玩家放置位置 | `<游戏目录>\bin\neko\plugins\cs2feel_aimsync.ini`（与 `cs2feel_aimsync.dll` 同目录；Left4Neko 启动时扫 `bin\neko\plugins\`） |
| DLL 来源 | **不在** `client\` 里：来自 `CS2FeelVScript_L4D2` 的 `client_src/cs2feel_aimsync/`（决策 D-058，机制见该仓库 `docs/TR40/README.md`） |
| 公式 | `ratio = cs2feel_ballistics_scale / cs2feel_recoil_scale` |
| 匹配 | `ratio = 0.0`（逐位惰性，什么都不改；`ballistics_mode 0` 时一律按 0.0） |
| CS2 原生分离 | `ratio = -0.090909` |

- `deploy.ps1` 不处理 `client\`：它只装服务器；客户端文件由玩家从发布包自取或手写。
- 随包 ini 默认就是 `ratio = 0.0`（匹配）。服务器切到 CS2 原生后，把 `ratio` 改成 `-0.090909`；菜单「后坐结构」页的 `r.client` / `r.split` 会显示当前应填的值（由服务器实时派生，见 `docs\02_菜单结构.md` §3.11）。
- 只放 ini 不放 dll 没有效果；只放 dll、没有 ini 也没有副作用（ratio 默认 0 = 逐位惰性）。
- 两边不一致**不影响**服务器子弹/命中，只会让客户端可见弹孔偏 `ratio` 倍 punch（AK 满自动约 0.53°，实测见 `docs\02_菜单结构.md` §3.11 的 `r.facts`）。服务器切档后 ini 会被热重载，不用重启游戏。
- 已知边界：客户端预测吃的是上一条命令的 punch，可见后坐仍比真实子弹滞后一发份（实测 1.76°）；本文件只在 `-insecure` / LAN 下使用，不要用于 VAC 服务器。

### 11.1 回滚

- **客户端**：删掉 `<游戏目录>\bin\neko\plugins\cs2feel_aimsync.ini` 与 `cs2feel_aimsync.dll` 两个文件。删完即回到“没装 aim-sync”的旧行为：服务器分离照常生效，子弹/命中不变，只是弹孔回到相机方向。
- **服务器**：在**同一页**点 `r.matched`，把 5 个值写回 `1.0 / 1.0 / 0 / 0.0 / 0` 并落盘；不需要卸载插件，也不影响其它受管值。`uninstall.ps1` 卸载的是整个整合包，与这两个档位无关。
